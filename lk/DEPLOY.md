# Личный кабинет: как запустить и обновлять — всё в браузере

Терминал, архивы и VPN больше не нужны. Всё устроено так:

- **Страница кабинета** — `https://nachert1830.ru/lk/`. Она лежит в этом репозитории (папка `lk/`) и публикуется
  вместе с сайтом (GitHub Pages). С основного сайта на неё нет ссылок, поисковикам она закрыта (`noindex`). Без входа
  видна только кнопка «Войти», а войти может только тот, кого пригласили.
- **Сервер кабинета** работает в Yandex Cloud (данные в России): аккаунты, прогресс, приглашения, бот. Он уже создан.
- **Обновляет облако сам GitHub.** При каждом изменении папок `lk/` или `server/` запускается
  «Кабинет — развёртывание в Yandex Cloud» (вкладка **Actions** репозитория): проверки → новая версия в облаке → бот.
- **Вход** — через **Яндекс ID** или **Telegram-бота**. К одному аккаунту можно привязать оба способа
  («Настройки» → «Способы входа»).

Сделать руками нужно один раз — три шага по 5 минут. Если что-то непонятно или красное — пришлите Claude скриншот
(только не присылайте содержимое ключей и секретов).

## Шаг 1. Ключ, которым GitHub обновляет облако

1. Откройте https://console.yandex.cloud → каталог **default** (тот, где уже лежит кабинет).
2. В поиске сверху наберите **«Сервисные аккаунты»** → откройте → **«Создать сервисный аккаунт»**.
   - Имя: `github-deploy`.
   - **Роли в каталоге** → «Добавить роль» → `admin`. (Это «робот», который будет создавать и обновлять части кабинета.
     Ему нужен полный доступ, но только к этому каталогу.)
   - «Создать».
3. Откройте `github-deploy` → сверху **«Создать новый ключ»** → **«Создать авторизованный ключ»** → «Создать» →
   **«Скачать файл с ключами»**. Скачается `authorized_key.json`.
4. Откройте этот файл Блокнотом → Ctrl+A → Ctrl+C. Он понадобится в шаге 3.

## Шаг 2. Приложение «Войти с Яндекс ID»

1. Откройте https://oauth.yandex.ru → **«Создать приложение»** (войдите своим Яндексом).
2. Название: `Кабинет Начерта`. Платформа: **«Веб-сервисы»**.
3. **Redirect URI** — вставьте ровно это:
   ```
   https://d5d8eabs4lpi7jqnu2ha.4kscn31j.apigw.yandexcloud.net/api/auth/yandex/callback
   ```
   «Suggest Hostname» (если спросит): `nachert1830.ru`.
4. **Доступы**: только **«Доступ к логину, имени и фамилии, полу»** (раздел «Яндекс ID»). Больше ничего не отмечайте —
   почта, телефон и прочее кабинету не нужны.
5. «Создать приложение». На странице приложения будут **ClientID** и **Client secret** — понадобятся в шаге 3.

## Шаг 3. Секреты в GitHub

https://github.com/nachert1830/nachert → **Settings** → слева **Secrets and variables** → **Actions** →
**New repository secret**. Добавьте четыре секрета (Name — слева, Secret — справа):

| Name | Что вставить |
|---|---|
| `YC_SA_KEY` | всё содержимое `authorized_key.json` из шага 1 |
| `YANDEX_CLIENT_ID` | ClientID из шага 2 |
| `YANDEX_CLIENT_SECRET` | Client secret из шага 2 |
| `OWNER_YANDEX_LOGIN` | ваш логин в Яндексе — то, что до `@yandex.ru`. С ним вы станете админом |

Токен бота и ваш Telegram id уже лежат в облаке с прошлого развёртывания — их добавлять не нужно.
После этого удалите `authorized_key.json` с компьютера: копия есть только в секретах GitHub, увидеть её там нельзя.

Готово. Напишите Claude «секреты добавил» — он сам запустит развёртывание и проверит, что всё зелёное.
(Или сами: **Actions** → последний запуск «Кабинет — развёртывание…» → **Re-run all jobs**.)

## Как войти

- Сейчас: откройте `https://d5d8eabs4lpi7jqnu2ha.4kscn31j.apigw.yandexcloud.net/` → **«Войти с Яндекс ID»** →
  «Разрешить» → отметьте документы → «Войти». Вы — владелец (админ).
- После того как ветка кабинета слита в `main` (pull request → Merge): кабинет открывается по `https://nachert1830.ru/lk/`.
  Ссылки входа и приглашений переключатся на этот адрес сами при следующем развёртывании.
- **Вход через Telegram** на nachert1830.ru/lk/ — официальный: страница Telegram → подтверждение в приложении Telegram
  (сообщение приходит от самого Telegram). Нужно один раз сказать Telegram адрес сайта: в Telegram откройте **@BotFather** →
  `/setdomain` → выберите бота кабинета → отправьте `nachert1830.ru`.
- **Бот кабинета сейчас не отвечает, и это не ошибка кода.** Серверы Telegram не могут соединиться с Yandex Cloud
  (Telegram пишет «Connection timed out»), и облако тоже не достаёт до Telegram. Поэтому на сайте вход через бота
  убран, и напоминания в Telegram не уходят. Вернуть их можно через посредника за рубежом (например, бесплатный
  Cloudflare Worker, который передаёт сообщения между Telegram и облаком). Развёртывание каждый раз проверяет бота и
  пишет в журнал, что видит Telegram: строки «до настройки: …» и «самопроверка вебхука».

## Регистрация

Регистрация открыта: на странице кабинета человек вводит почту (приходит код) или нажимает «Войти с Яндекс ID». Новому
один раз показывается «Добро пожаловать»: имя и две отметки (соглашение и согласие на обработку данных) — без них аккаунт
не создаётся. Ссылок-приглашений больше нет; на самом сайте кабинет нигде не упомянут, поисковикам страница закрыта.
Закрыть регистрацию снова — переменная функции `OPEN_SIGNUP=off`.

## Вход по почте (включить один раз)

Письма с кодом отправляет Yandex Cloud Postbox (серверы в России). Адрес почты кабинет не хранит — только его хеш.
Развёртывание само добавляет домен `nachert1830.ru` в Postbox и создаёт ключ подписи писем (DKIM). От вас — одна запись
у регистратора домена (reg.ru → домен → «DNS-серверы и управление зоной» → «Добавить запись»):

- тип **TXT**, имя (поддомен) **`club._domainkey`**, значение — строка `v=DKIM1; k=rsa; p=…` из журнала развёртывания
  (Actions → последний запуск «Кабинет — развёртывание…» → шаг «Развернуть» → раздел «Почта (Yandex Postbox)»). Claude
  пришлёт её текстом.

Postbox проверяет запись сам (обычно до часа). Следующее развёртывание увидит «домен подтверждён» и включит вход по
почте: на странице кабинета появится поле «Почта → Получить код». Перезапустить развёртывание можно кнопкой Re-run.

## ИИ-зрение сканера (глаза)

Сканер чертежей в кабинете («Проверка» → «ДЗ № 2–3 по начерту») может попросить модель со зрением прочитать фото:
где подписанные точки условия (A″, B′, …), сколько чертежей на листе и какая часть на каждом. Меряет и выносит вердикт
не она, а сканер — по линиям листа. С глазами не нужны рамка, штамп, клетки и края листа; у ДЗ № 3 проверяются все
четыре чертежа листа сразу. Фото не сохраняется: только запрос к модели.

**По умолчанию** — модель зрения в Yandex AI Studio (тот же каталог Yandex Cloud, данные в России). Ключ не нужен:
функция кабинета ходит с IAM-токеном своего сервисного аккаунта, развёртывание само выдаёт ему роль
`ai.languageModels.user`. **Модель подбирается сама:** развёртывание отправляет пробное фото (четыре круга — «сколько?»)
известным моделям зрения (Qwen3.6, Alice AI, Gemma 3, Qwen2.5-VL), а затем остальным моделям из списка каталога, и подключает
первую, что ответила верно: значит, она видит картинку (не все модели AI Studio есть в синхронном режиме — на остальные
Yandex отвечает 400/403). В журнале (шаг «Развернуть» → «ИИ-зрение сканера») видно, какая подключена, а если ни одна —
причина от каждой. Задать модель или адрес вручную — в GitHub → Settings → Secrets and variables → Actions → **Variables**:

| переменная | что это |
|---|---|
| `EYES_MODEL` | модель, `{folder}` заменяется на каталог; если задана — проверяется только она (без неё — подбор) |
| `EYES_URL` | адрес OpenAI-совместимого `/chat/completions`; по умолчанию `https://llm.api.cloud.yandex.net/v1/chat/completions` |
| `EYES` | `off` — выключить глаза |

Модель не из Yandex Cloud (любой сервис с OpenAI-совместимым API и картинками): `EYES_URL`, `EYES_MODEL` и секрет
**`EYES_KEY`** (ключ API; заголовок `Authorization: Bearer <ключ>`, для `Api-Key` — переменная `EYES_AUTH=Api-Key`).

### Точнее: Claude (или другая зарубежная модель) через ProxyAPI

Модель в Yandex — основная и работает всегда. Зарубежная «лучшая» модель (по умолчанию Claude Sonnet, оцифровка — тоже
Sonnet; Opus дороже, и ProxyAPI требует на балансе запас под завышенную оценку запроса) идёт через [ProxyAPI](https://proxyapi.ru) — российский сервис с оплатой в рублях и единым OpenAI-совместимым
адресом `https://api.proxyapi.ru/v1/chat/completions` (ключ — `Authorization: Bearer <ключ>`). Сама модель зарубежная:
фото уходит за рубеж, поэтому нужно согласие; без него, без ключа или если модель не ответила за 35 с — снова Yandex.
Подключить:

1. console.proxyapi.ru → «Ключи API» → создать ключ (и пополнить баланс в рублях).
2. GitHub → Settings → Secrets and variables → Actions → **Secrets** → `PROXYAPI_KEY` = ключ. Старый секрет
   `OPENROUTER_API_KEY` кабинету больше не нужен (развёртывание само убирает его из Lockbox; для замеров в
   `lab/dz` он пока используется).
3. Развернуть: Actions → «Личный кабинет — развёртывание» → Run workflow.
4. Другая модель — **Variables** → `EYES_BEST_MODEL` (имя с вендором, как в каталоге ProxyAPI: `anthropic/claude-opus-5-5`,
   `anthropic/claude-sonnet-5-5`, `google/gemini-…`; имя в духе OpenRouter `anthropic/claude-opus-5.5` тоже примется) →
   развёртывание. `EYES_BEST_MODEL=off` — выключить.
5. В сканере: отметка «Лист мой…» → под ответом «ИИ-зрение (anthropic/claude-…) ответило».

Проверить: после развёртывания открыть сканер в кабинете — появится галочка «ИИ-зрение». Если модель недоступна,
сканер напишет причину («Модель зрения ответила ошибкой 404: …») и проверит фото без неё. Лимит — 40 фото в час на
участника.

## Пульт владельца

Вкладка **«Пульт»** (видна только админам) — живая картина, обновляется сама каждые 8 секунд: кто сейчас в кабинете и на каком
экране, лента действий (регистрации, входы, решённые задачи — сам / с подсказкой / не смог, проверки чертежей, пробные РК),
активность по часам, «где спотыкаются» (задачи, которые чаще всего не получаются), группы за сегодня. Нажмите на человека —
его карточка: что делал, сколько решил сам, сколько задач в повторении. Журнал действий хранится 30 дней; в нём нет
содержимого решений и фото — только «что и когда».

## Расписание групп

Участник указывает группу при регистрации (или в «Настройках»). Дни занятий и точные даты событий по группам — в файле
`lk/data/groups.json`: как только там есть группа участника, его календарь и верхняя строка считаются по ней.

## Админ-панель

«Ещё» → «Админ-панель»: **«Участники»** (роли, закрыть доступ), **«Функции»** (включить и выключить), **«Отзывы»**,
**«Входы»**, **«Семестр»** — дата понедельника первой учебной недели (по умолчанию 31.08.2026).

## Если что-то сломалось

- **Красный крестик в Actions.** Откройте запуск → шаг с крестиком: внизу будет понятная строка с «✖» или
  «::error::» — что именно не задано или не получилось. Пришлите её Claude.
- **«Яндекс ID сейчас не ответил»** при входе — проверьте, что Redirect URI в приложении на oauth.yandex.ru совпадает
  с адресом из шага 2 буква в букву.
- **Токен бота утёк.** @BotFather → `/revoke` → новый токен → добавьте его секретом `TG_BOT_TOKEN` в GitHub и
  перезапустите развёртывание: скрипт заменит токен в облаке. После этого секрет можно удалить.
- **Удалить кабинет полностью.** Консоль Yandex Cloud → каталог → удалите базу `club`, функции `nachert-club-*`, шлюз
  `nachert-club`, секрет `club-secrets`. Удалятся все данные участников — по правилам кабинета их нужно предупредить
  за 14 дней.

Что закон требует от вас как от оператора персональных данных (по 152-ФЗ):

1. **Отвечать на обращения в течение 10 рабочих дней.** Они приходят в «Админ-панель» → «Отзывы» с пометкой «Обращение к

   «Уведомление о намерении осуществлять трансграничную передачу». Получатель — Telegram Messenger Inc., цель — «вход и
   напоминания участникам по их просьбе», данные — Telegram id, имя и текст сообщений бота. Вход через Яндекс ID
   трансграничной передачи не создаёт: ООО «Яндекс» и Yandex Cloud — в России.
3. **Общее уведомление об обработке ПД** (ст. 22), по-видимому, не нужно: данные получены для исполнения соглашения с самим
   участником и третьим лицам без его согласия не передаются (п. 2 ч. 2 ст. 22).

## Что делает развёртывание (для любопытных)

`.github/workflows/club.yml` → `server/tools/deploy.js`. Повторный запуск безопасен: что уже есть — не пересоздаётся.

1. Проверки: `server/test/*` и логика кабинета `lk/tests/lib.test.js`.
2. Ставит программу `yc` и входит ключом из `YC_SA_KEY`.
3. Сервисные аккаунты `club-fn` (функции: база и сейф) и `club-gw` (шлюз и таймер: запуск функций).
4. База `club` (YDB serverless, ru-central1) и таблицы.
5. Сейф `club-secrets` (Lockbox): ключ базы, токен бота, секрет вебхука, Client secret Яндекс ID. Значения не выводятся
   ни в журнал, ни на диск.
6. Функции `nachert-club-api` и `nachert-club-remind`, шлюз `nachert-club` по `server/apigw.yaml`, новая версия кода
   с настройками (адрес, имя бота, владелец, ClientID, адрес страницы кабинета) и ключами из сейфа.
7. Таймер напоминаний (каждые 15 минут), вебхук бота и команды — с сервера GitHub, ему Telegram доступен.
8. Записывает адрес API в `lk/config.js` и CSP `lk/index.html` — чтобы страница на nachert1830.ru знала, куда
   обращаться. Если адрес поменялся, делает коммит в ту же ветку.

Ссылку для входа владельца без Яндекса и Telegram можно получить и с компьютера с программой `yc`:
`node server/tools/login.js` (запасной путь).

Локальная эмуляция без облака: `node server/dev.js --site-port=8788` → `http://localhost:8788/lk/` (как на сайте) или
`http://localhost:8787/`; Яндекс ID и бот там поддельные, владелец — логин Яндекса `owner` или Telegram id `1000001`.
