# Проверка сайта

`node tests/run.js` — полная проверка (её же запускает GitHub после каждого изменения, см. вкладку Actions).

| Файл | Что проверяет |
|---|---|
| `geometry.js` | Каждый чертёж восстанавливается в 3D по проекциям A′, A″. Проверяются линии связи (в том числе π₃), принадлежность и деление отрезка в одном отношении, конкурирующие точки, видимость (штрих — точку закрывает плоскость, которая ближе), размеры и углы на чертеже, утверждения в тексте шагов (∥, ⊥, ∈, «пересекаются/скрещиваются», \|AB\|, координаты), одна точка — одно имя. Число на чертеже = та же величина в тексте задачи (условие, шаги, ответ). Штриховая линия — только там, где её перекрывает фигура (грань, многоугольник, окружность); точка без подписи — на линии; конец размерной линии — напротив точки или на линии. Десятичный знак — запятая. Вердикт не зависит от порядка элементов на чертеже. |
| `render.js` | Чертежи рисуются в ширину телефона: подписи не налезают друг на друга и на точки, не выходят за край. |
| `mutate.js` | Проверка проверки: в настоящие чертежи подсаживаются ошибки (разрыв линии связи, перепутанные подписи, неверное число) и считается, сколько поймано. Чертёж проверяется вместе с текстом задачи, как на сайте. `MUTATE_SIZES` — полный перебор: каждое число на чертежах меняется на −3, +3, +6, +9 мм (порог в `run.js` — 95 %). |
| `theory.js` | Факты курса и шаблоны их неверных формулировок; верные ответы тестов не должны совпадать с шаблоном ошибки. |
| `oracle.js` | Оракул: для всех 89 задач (125 из 130 частей) условие записано геометрически («K ∈ a и AK ⊥ a», «O равноудалена от сторон»), ответ на чертеже проверяется линейной алгеброй — независимо от того, как он построен. Углы в тексте ответа сверяются с вычисленными. Поверхности (сфера, конус, тор, цилиндр) читаются с самого чертежа: очерки, окружности, вершина. Без проверки ответа — 5 частей: 73 в, 74 б, 74 в, 89 б, 89 в (параметры поверхностей на чертеже не подписаны). 68 в — геликоид: ось, образующая и шаг с чертежа, направление винта — по точкам A₁…A₁₁; 77 в — косая плоскость: направляющие и плоскость параллелизма α (следы), с полнотой ответа. |
| `random.js`, `random-run.js` | Случайные варианты: исходные данные каждой задачи искажаются (равные числа — одинаково, нули остаются нулями), задача строится заново и проходит 3D-проверку и оракул. Верный метод верен на любых данных; подогнанная точка или число, набранное руками, дают противоречие. `node tests/random-run.js --seeds=100` — отдельный прогон. |
| `gen-check.js`, `gym.js` | Тренажёр (#/ng/check/gym). Генератор вариантов на сайте ищет блоки задач так же, как контрольный разбор acorn; список задач для генератора (GEN_OK) пересчитывается: вариант должен проходить проверку, а числа в тексте — меняться вместе с данными. Каждый режим проверяется нажатиями: «построй сам» принимает верный ответ и отклоняет неверный, «найди ошибку» засчитывает нажатие на ошибку и не засчитывает мимо. Скрытые функции: окно «3D к задачам» открывается и листает шаги. |
| `provenance.js`, `provenance-run.js` | Трассировка происхождения: каждая точка чертежа помнит, с какого поля она построена (F — фронтальная проекция, H — горизонтальная) и через какие построения прошла. Подпись A′ должна стоять в точке горизонтальной проекции, A″ — фронтальной; отрезок не может соединять два поля; линия связи — вертикальна, горизонтальна или перпендикулярна новой оси при замене плоскостей. Ловит «не ту проекцию», которую по готовому рисунку не отличить. |
| `adequacy.js` | Проверка проверки на мутациях КОДА задач: F↔H, не та координата, не тот знак, опечатка в числе, не тот штрих, видимая ↔ штриховая. Мутант без видимых изменений не считается. `node tests/adequacy.js --per=40` — подробный замер, `--only=46,47` — только эти задачи. Каждый выживший мутант разобран: «данные» — опечатка в числе, которое генератор вариантов меняет как исходные данные (та же программа на других данных); «условие» — изменился чертёж «дано» (нужна сверка с тетрадью); «оформление» — другие только длины отрезков (эквивалентный); «пропуск» — построение изменилось, а проверка молчит. |
| `certified/` | Сертифицированный эпюр. Задача записана протоколом шагов и исполняется дважды: в пространстве (по определению) и на эпюре (линейкой и циркулем), в точных дробях. На каждом шаге проекции обязаны совпасть точно (O1); ответ проверяется условием (O2) и независимым решателем, включая полноту (O3); опубликованный чертёж, видимость и число в ответе сверяются с доказанной моделью (O4, O5); метод — на 200 случайных данных (O7); условие — двумя вводами (O9). `node tests/certified/run.js --faults` — показывает, какая подсаженная ошибка каким обязательством ловится. Сейчас — № 46 и № 47. |
| `eskd.js` | **Реестр норм ЕСКД** (`window.ESKD` в `index.html`) — единственный источник чисел ГОСТ: из него листы ИГ строятся (толщины, штрихи, шрифты, отступы), по нему нормоконтроль проверяет, из него теория берёт числа и ссылки на пункт. Проверяется сам реестр: у каждой нормы стандарт, пункт, цитата и статус сверки (`text` / `web` / `mem`; `МУ` — методические указания, не ГОСТ); профиль листа внутри норм; числа ЕСКД в тексте сайта против реестра (с проверкой проверки: 11 неверных формулировок ловятся, 11 верных — нет); цитаты против текстов стандартов в `docs/gost/` (`docs/gost/README.md`). Подробно — docs/gost-ig.md, раздел 7. |
| `normo.js`, `normo-model.js`, `normo-run.js` | Нормоконтроль листов ИГ (30 вариантов ДЗ 2, чистовик и черновик, лист урока) по готовому SVG — то, что видит студент. ГОСТ 2.301–2.307, 2.316 и ГОСТ Р 2.104, числа и пункты — из реестра `window.ESKD`: формат, рамка, основная надпись, масштаб, одна толщина основной линии и линий каждого типа, тонкие s/3…s/2, размер шрифта из ряда, буквы ≈ вдвое крупнее размерных чисел, штрихи штриховой и штрихпунктирной, оси пересекаются и кончаются штрихами и выходят за контур на 2…5 мм, шрифт, проекционная связь, половина разреза справа, обозначения разрезов, штриховка, числа не пересекаются линиями, размерные линии ≥ 10 мм от контура. Сверка с 3D-моделью лучами: лишние и пропущенные линии, видимое/невидимое, штриховка там, где секущая плоскость прошла по материалу. `node tests/normo-run.js [--nomodel] [--only=8] [--shots=папка]`. Подробно — docs/gost-ig.md, раздел 5. |
| `euclid.js` | **«Евклид» — построимость.** Чертёж читается как доказательство: каждый элемент должен выводиться из уже построенных действиями линейки и циркуля, и каждое действие проверяется счётом. Прямая — через две известные точки одного поля или через одну точку ∥ / ⟂ построенной прямой (оси); точка — пересечение двух построенных линий или перенос циркулем известной длины (нарисованный отрезок, координата, разность координат, длина из условия), параллельный перенос отрезка, деление в том же отношении; дуга — из известного центра, с концами в построенных точках; знак ⊾ — угол действительно 90° и стоит на построенных линиях; подпись угла — измеренный угол; «прямая» между точками разных полей (A″–1′) — не построение. «Дано» — аксиомы. Невыводимое — «взялось ниоткуда». Кривые поверхности: очерк — огибающая, параллель и меридиан — из известного центра и радиуса, кривая пересечения — через построенные точки. Проверяет 87 задач из 89 и ДЗ №2–3; в работе — `EUCLID_TODO` (№74, №77). |
| `dz.js`, `dz-run.js` | **ДЗ-оракул.** Разборы ДЗ №2 (2а–2в) и №3 проверяются числами, независимо от кода построения: условие — из таблицы данных и текста условия; ответ удовлетворяет каждому условию (S ∈ EF и d(S, ABC) = 80; AB = AC; AB ⟂ AK…); промежуточные точки — там, где их требует метод; замена плоскостей (линия связи ⟂ новой оси, сохраняемая координата со знаком); вращение вокруг прямой уровня (след, центр, радиус-гипотенуза); видимость рёбер и данных прямых — лучом к наблюдателю; штриховая — только там, где тело закрывает; каждое «X(x; y; z)», «\|XY\| = …», «точка на уровне z = …» в тексте — по чертежу. Дуга окружности начинается и кончается в построенных точках; катет Δz треугольника радиуса вращения — ровно Δz и ⟂ радиусу. `node tests/dz-run.js --seeds=100` — разборы на случайных вариантах (у каждого студента свой вариант), `--mutate` — проверка проверки на мутациях кода ДЗ. |
| `arith.js` | Арифметика текста: каждое «выражение = число» в пояснениях («R = √(23,6² + 30²) = 38,2», «φ = 90° − 40,4° = 49,6°») пересчитывается по напечатанным числам. |
| `false-positives.js` | Ложные срабатывания: эталоны (172 чертежа), итоговый чертёж с элементами в другом порядке, шаги в другом порядке (справочно). `node tests/false-positives.js`. |
| `normo-mutate.js` | Проверка проверки нормоконтроля и честность тренажёра «Нормоконтроль»: 13 типов нарушений тренажёра подсаживаются в настоящие листы, каждое должно ловиться в области, которую тренажёр показывает как ответ, без лишних замечаний. Плюс прогон нажатиями: тренажёр (попал / мимо / верный лист) и «Читаю чертёж» (линия подсвечивается на всех видах). `wavyMutations` — сторона волнистой линии (ГОСТ 2.305): в каждый лист, где граница вида и разреза волнистая, подсаживаются «волнистая в другую сторону» и «граница — ось»; ловиться должны все. |
| `run.js` | Всё вместе + обход всех страниц на экране телефона (ошибки, горизонтальная прокрутка) и прохождение каждой задачи до ответа. «Научись защищать точки» (#/ig/points): каждая точка разбора лежит на поверхности детали (точка в штриховке — в секущей плоскости), видимость, под которую написан текст, совпадает с видимостью по модели на изображениях листа (луч к глазу, разрезы как на листе: выколотая точка или крестик); тренажёр нажатиями — верное место и отметка засчитываются, перепутанные перёд и зад или не та отметка — нет. |
| ДЗ №3 в `run.js` | «Сверь свой лист» ДЗ №3: таблица 30 вариантов задания — ответы (высота, двугранный угол при AB, стороны ABC, угол SA с основанием) пересчитываются независимо и сверяются с показанными на сайте; выбор варианта подставляет его данные; ответы варианта, вписанные как свои, проходят проверку. |
| `baseline.json` | Случаи «проверить», разобранные вручную, с объяснением, почему это не ошибка. |
