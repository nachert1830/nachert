# Голограмма: вентиль и деталь варианта 5 под управлением рук

Отдельная страница `hands/` — деталь варианта 5 (задача 2 «Построение изображений»), которой управляют жестами
рук перед веб-камерой, в духе интерфейса Тони Старка. Основной сайт (`index.html`) не тронут; геометрия берётся из того
же дерева IG3, что и на сайте.

Запуск (камере нужен `localhost` или `https`):

```bash
python3 -m http.server 8000
```

Затем открыть http://localhost:8000/hands/ и нажать «✋ Включить руки». Видео никуда не отправляется: руки распознаёт
MediaPipe прямо в браузере (модель и wasm — в `vendor/`, без CDN).

## Модели

- **Вентиль угловой запорный** (по умолчанию) — сборочная единица из 12 позиций: корпус, крышка, прокладка, шпиндель
  с трапецеидальной резьбой, клапан, набивка сальника, нажимная втулка, накидная гайка, маховик, гайка маховика,
  шпильки и их гайки. Данные — `valve-data.js` (`tools/build-valve.js`: детали — деревья IG3, резьба — своя
  процедурная сетка), описание — `model-valve.js`.
  - **Механизм**: ползунок «Вентиль» на панели или клавиша `O` — маховик со шпинделем вращаются,
    шпиндель по резьбе крышки поднимается (шаг 4 мм, ход 14 мм), клапан отходит от седла, по каналу идёт поток.
  - **Разбор** — в порядке, обратном сборке; выноски с номерами позиций двумя колонками, как на сборочном чертеже.
  - **Разрез** — у каждой детали своя штриховка по ГОСТ 2.306 (у смежных — разный наклон и шаг, прокладка — сплошь,
    набивка — сеткой); шпиндель, шпильки и гайки в продольном разрезе не рассекаются (ГОСТ 2.305).
  - **Тест** — вопросы про сборку («покажи деталь, которая уплотняет шпиндель» и т. п.).
- **Вариант 5** (`?m=v5` или меню «Ещё») — деталь задачи 2: фланец и усечённый конус с пирамидальным отверстием.

## Жесты: «наведи и щипни»

Три позы — **щипок**, **открытая ладонь** и «всё остальное». Новых поз не вводим, а смысл щипка задаёт то, что под
курсором. Хлопок, щелчок пальцами, «лезвие», два кулака и «руль» убраны: на 15–30 кадрах/с веб-камеры их нельзя
распознать надёжно (касание ладоней рвёт трекинг, щелчок короче кадра, ребро ладони непрерывно переходит в ладонь).

| Жест | Действие |
|---|---|
| 👆 рука в кадре | курсор — у основания указательного `(2·p5 + p9)/3`: при щипке почти не сдвигается (кончик съезжает на 3–5 % кадра) |
| 👆 курсор на детали 0,12 с / 0,3 с | подсветка / название детали («пузырь»: ближайшая в радиусе 20–40 px) |
| 🤏 щипок по кнопке | нажатие **на отпускание**: щипок ≤ 0,8 с и курсор ушёл < 40 px, иначе отмена |
| 🤏↔ щипок по ползунку | захват: ползунок едет за рукой (и дальше края экрана), пока пальцы сомкнуты |
| 🤏 щипок по пустому месту | сразу вращение; отпустил на ходу — инерция |
| 🤏 щипок по детали | 0,4 с решают: повёл (> 0,025 кадра) — вращение; держишь (< 0,015) — **деталь вынимается** вдоль оси разборки; отпустил на > 40 % хода — остаётся, иначе пружиной назад |
| 🤏⟳ щипок по маховику | крути рукой по кругу: против часовой — открыть; 1 оборот руки = 30 % хода |
| 🤏↔ щипок по красной ручке разреза | секущая плоскость едет вдоль своей оси |
| 🤏🤏 два щипка | разводить — зум, вести вместе — сдвиг (мёртвые зоны 4 % и 0,01 кадра); руки ближе 1,5 ладони — заморозка |
| ✋ ладонь 0,5 с | радиальное меню у курсора: Вид ▸, Разрез ▸, Эпюр, Разобрать, Открыть, Тест; центр — сброс (6 с — «↶ Вернуть») |
| ✊ кулак в меню | закрыть меню |

В тесте «Проверь себя» ответ — щипок с удержанием 0,4 с на детали (или щелчок мышью).

Мышь и касания работают всегда: тянуть — вращать, колесо — зум, правая кнопка или Shift — сдвиг,
два пальца — зум и сдвиг, двойной щелчок — сброс; панель — обычными щелчками и перетаскиванием, ползунки — ещё
и стрелками. Клавиши: `E` — разобрать/собрать, `O` — открыть вентиль, `Alt`+колесо — разбор плавно,
`R`/`Esc` — сброс, `X` — следующий разрез, `V` — следующий вид, `M` — эпюр, `H` — тема, `S` — звук, `C` — камера, `Z` — запись.

### Машина состояний (`gestures.js`)

`idle` → `pending` (щипок по детали) → `rotate` | `drag`; `idle` → `drag` (кнопка, ползунок, маховик, плоскость);
`idle` → `rotate` (пусто); `rotate`/`pending` + щипок второй руки → `zoom` → `wait` (до нового щипка); `idle` → `arm`
(ладонь) → `menu`. Пока одна рука держит захват или меню, щипок второй игнорируется. Рука пропала ≤ 250 мс — состояние
держится, по возвращении — без скачка; дольше — жест кончается без инерции, значения остаются.

### Защита от ложных срабатываний

| Механизм | Как работает |
|---|---|
| Пороги в долях ладони | щипок `|4−8|/ладонь` < 0,30 вкл., > 0,48 выкл. |
| Время и кадры | поза засчитывается через ≥ 60 мс **и** ≥ 2 кадра, щипок снимается через 100 мс; при < 12 кадрах/с — на 30 % дольше, без инерции, магнит кнопок 30 px |
| Не кулак | щипок только при `|8−0|/|5−0|` > 1,20 |
| Не смаз | щипок не начинается при скорости ладони > 2 ладоней/с |
| Край и расстояние | ближе 3,5 % к краю или ладонь < 4,5 % кадра — рука не управляет; < 8 % — предупреждение |
| Курсор | рабочая зона кадра x 0,27–0,73, y 0,30–0,74 растянута на экран; 1€ (0,8 Гц, β 14); залипание 0,45 % экрана |
| Цель щипка | где был курсор за 80 мс до смыкания |
| Перестановка рук | треки по положению ладони, метка «левая/правая» почти не весит |

## Что на экране

- **Тёмная тема (по умолчанию) — голографический стенд «как у Тони Старка»**: почти чёрный синий фон со свечением
  проектора и точечной сеткой, деталь — циановая голограмма (Френель по контуру, полосы интерференции ползут вверх,
  луч сканирования), на полу — вращающиеся кольца проектора с рисками; оранжевый — действие и наведение.
  Поверх: кольца-целеуказатель вокруг модели со шкалой азимута, лента азимута сверху и шкала тангажа слева
  (ярко — пока модель вращают), блок «Телеметрия» (азимут, тангаж, масштаб, разбор, вентиль, руки и частота),
  **захват детали** — скобки по её экранной рамке и карточка «Анализ детали» (позиция, имя, материал, габарит),
  загрузка стенда при первом показе (2,4 с; без анимации при reduced motion). Панели — стекло со срезанными углами,
  моноширинные заголовки со свечением, ползунки-шкалы с ромбом-ручкой.
- **Светлая тема — «чертёж»**: белый лист, детали — реалистичный металл по материалу из спецификации
  (чугун СЧ — серо-синий матовый, сталь — светлая глянцевая, латунь клапана, графитовая набивка, паронитовая прокладка):
  рассеянный свет, отражение «студии», блик, Френель, мягкая тень на полу; линии — тёмно-синие, разрез — красный.
- **Штриховка разреза сглажена** по ширине пикселя (`OES_standard_derivatives`): на мелком шаге нет муара.
- **Разбор**: с 55 % — выноски с названиями частей (у сборки — двумя колонками с номерами позиций).
- **Поверх 3D**: курсор руки (кольцо сжимается по мере щипка, щипок — красный диск), дуги удержания (деталь 0,4 с,
  меню 0,5 с), подпись «что сейчас под управлением», радиальное меню, ручки плоскости и маховика, мини-скелет руки
  (когда нет превью камеры), полоса «рука у края кадра», «ближе/дальше от камеры», «не сводите руки».
- **Звук**: тихие синтезированные щелчки на щипок, нажатие, «взял деталь», меню, щелчки маховика и сброс. По умолчанию выключен (🔇).
- `prefers-reduced-motion`: без инерции, мерцания, луча и анимации сброса.

## Телефон как датчик рук

Если ноутбук не тянет распознавание, руки можно распознавать на телефоне, а картинку оставить на ноутбуке.

1. На ноутбуке — «📱 Телефон»: появится QR-код.
2. Айфон наводит на него камеру и открывает ссылку — страница-датчик сама запускает камеру и MediaPipe; нужно только разрешить камеру.
3. Всё. Работает в одной сети Wi-Fi, с VPN, через мобильный интернет.

Связь двумя путями сразу:
- **брокер MQTT** (публичный, по WebSocket: broker.emqx.io, запасной — broker.hivemq.com; клиент — `mqtt.js`, без библиотек). Через него устройства знакомятся, и через него же идут точки рук, если прямого канала нет (VPN, разные сети). Канал — случайное имя из 128 бит;
- **прямой канал WebRTC** — если устройства видят друг друга (одна сеть, без VPN): быстрее; телефон сам переключается на него, когда он сложился.

В обоих случаях передаются только координаты пальцев (~0,5 КБ на кадр; пустые кадры — каждый пятый, как «я на связи»). Видео остаётся на телефоне. Телефон пишет ноутбуку, что у него происходит («распознавание готово», «прямой канал открыт» и ошибки) — видно в окне сопряжения и поверх голограммы.

Распознавание на телефоне — в основном потоке, одним экземпляром облегчённой модели (воркер на iOS не запускался); модель прогревается во время знакомства. Экран не гаснет, пока страница открыта (Wake Lock).

Сквозной тест: `node hands/tests/pair.js` — две вкладки Chromium и мини-брокер MQTT в тестовом сервере; сценарии «как с VPN» (только брокер) и «одна сеть» (переход на прямой канал). Safari в контейнере проверить нечем — только на телефоне.

## Для учебы

- **📐 Эпюр (угол Монжа).** Вокруг детали три плоскости проекций П₁, П₂, П₃ с живыми проекциями: видимые линии сплошные, невидимые — штрихом (видимость считается лучами). Вторым нажатием угол разворачивается в эпюр: главный вид, под ним вид сверху, справа вид слева, в проекционной связи. Клавиша `M`.
- **🎯 Тест («Проверь себя»).** Деталь разобрана, страница просит показать часть: фланец, конус, вынутый материал отверстий. Ответ — указательным пальцем (задержать 0,9 с) или щелчком мыши. Засчитываются ответы с первой попытки; подписи частей в тесте скрыты.
- **Разрез** — кнопки «Гориз. / Фронт. / Проф.» на панели, положение плоскости — ползунком; сечение заштриховано по ГОСТ 2.306.

## Интерфейс

Слева — режимы (на телефоне — снизу), справа — **панель управления моделью** (на телефоне — шторка снизу).
Все элементы крупные (кнопки ≥ 40 px, ручка ползунка 26 px), чтобы в них попадать рукой.
- **Панель справа**: «Разбор» (ползунок), «Вентиль» (ползунок открытия, у модели с механизмом), «Разрез»
  (нет / горизонтальный / фронтальный / профильный + ползунок положения), «Вид» (главный / сверху / слева / изо),
  «📐 Эпюр» и «↺ Сброс».
- **Слева**: ✋ Руки (камера), 📱 Телефон, 🎯 Тест, 🌙 Тема, 🔇 Звук, ? Жесты; **⋯ Ещё**: другая модель,
  обучение жестам, запись точек рук, повтор записи, диагностика скорости.

При первом включении камеры запускается обучение из 6 шагов. Каждый шаг засчитывается, когда жест действительно сделан. Внизу экрана — подсказка только с теми жестами, которые уместны сейчас.

## Скорость

- **Калибровка делегата.** При первом включении рук страница по 2,5 с гоняет MediaPipe на GPU и на CPU. Оценивает и скорость распознавания, и плавность экрана, выбирает лучшее и запоминает для этой видеокарты.
- На встроенной графике MediaPipe-GPU делит видеокарту с голограммой: руки быстрые, а экран дёргается. Поэтому плавность экрана входит в оценку.
- Разрешение рендера снижается само, если экран не успевает.
- **Облегчённая модель и «вторая рука по требованию»** — главное ускорение распознавания. Замер на фото рук (CPU, отслеживание): полная модель на 2 руки — 124 мс на кадр; облегчённая на 1 руку — 36 мс. Если ждать 2 руки, а в кадре одна, MediaPipe на каждом кадре заново ищет ладонь по всему кадру — это половина времени. Поэтому в воркере два экземпляра облегчённой модели: на 1 руку — каждый кадр, на 2 руки — раз в 6 кадров ищет вторую; нашлась — работаем с двумя, пока она в кадре. Через воркер без помех: одна рука — 35 мс (медиана), две — 62 мс.
  - Облегчённая модель — `hand_landmark_lite.tflite` из `@mediapipe/hands` (Apache 2.0); MediaPipe Tasks требует в модели TFLite-метаданные, их вписывает `tools/build-lite-task.py` (копия из полной модели — входы и выходы совпадают). Точность: ~3 px на кадре 480 px от полной модели.
- **Точка хватки — центр ладони**, а не середина щипка: при размыкании пальцев середина щипка сдвигается и доворачивала деталь.
- **Сглаживание быстрее**: фильтр 1€ со срезом 4 Гц (задержка ~40 мс вместо ~70), хватка засчитывается за 50 мс.
- **Плашка вверху во время работы рук**: частота камеры, частота рук и время распознавания. Если камера даёт меньше 20 кадров/с (полутьма) или руки меньше 15/с — подсказка, что сделать.
- **Профиль слабой графики** включается сам для встроенной Intel HD/UHD без Iris и для программного рендера: без MSAA (Chrome на этих чипах помечает его «неприемлемо медленным» — `msaa_is_slow`), разрешение 3D с 80 %, не чаще 30 кадров/с, распознавание рук сначала на процессоре. При программном рендере на странице появляется подсказка включить аппаратное ускорение.
- **📋 Диагностика** (меню «Ещё») копирует в буфер отчёт: видеокарта, браузер, частоты рук и экрана, результат калибровки.

## Как устроено

| Файл | Что делает |
|---|---|
| `gestures.js` | Вся логика жестов. Чистая: ни DOM, ни камеры — точки и время на входе, вид и события на выходе |
| `holo.js` | WebGL-рендерер (WebGL 1). Камера та же, что у `IG3.viewer`, плюс раскладка разбора (`layout(e)`) |
| `hud.js` | Слой 2D поверх 3D: руки, выноски, шкала, рамка |
| `app.js` | Сборка: камера, MediaPipe, мышь, клавиши, запись и повтор, `window.__feed` |
| `detector.worker.js` | MediaPipe в отдельном потоке: рендер не ждёт распознавания |
| `sound.js` | Звук на Web Audio |
| `pair.js`, `link.js`, `mqtt.js`, `sensor.html` | Телефон как датчик рук: QR-сопряжение, брокер MQTT, WebRTC, страница-датчик |
| `coach.js` | Обучение жестам и контекстная подсказка |
| `monge.js` | Угол Монжа: проекции на П₁, П₂, П₃ с видимостью, развёртка в эпюр |
| `v5.js`, `valve-data.js` | Геометрия моделей (генерируются) |
| `model-v5.js`, `model-valve.js` | Описание модели: раскладка разбора и механизма, подписи, вопросы теста, поток |
| `models.js` | Блок IG3 из `index.html` (генерируется, нужен только сборщику `v5.js`) |

### Распознавание

- MediaPipe Hand Landmarker, режим VIDEO, до 2 рук, кадр 640×480, не чаще 33 раз в секунду.
- Распознавание идёт в воркере, по одному кадру за раз. Если воркера нет, всё работает в основном потоке.
- Делегат выбирается так:
  - сначала GPU;
  - если GPU не создался или упал — CPU;
  - если GPU работает, но кадр стабильно дольше 45 мс (программный WebGL), пробуется CPU и остаётся более быстрый.
- Текущий делегат, частота и время кадра показаны в правом нижнем углу.

Разрез рисуется честно: отсечение в шейдере и плоская «крышка» с штриховкой 45° через стенсил-буфер (чётность пересечений).
Убирается половина, обращённая к зрителю.

- страница работает под своей CSP без ошибок;
- WebGL рисует деталь;
- `window.__feed` с синтетическими руками: вращение, курсор, кнопка и ползунок щипком, маховик, меню и сброс;
- MediaPipe стартует под CSP;
- путь камеры целиком на поддельной камере Chromium: `getUserMedia` → воркер → цикл распознавания.

### Подбор порогов по реальной камере

1. На странице включить руки и нажать «● Запись». Записываются только 21 точка каждой руки, видео не пишется.
   Сделать 20–30 с каждого жеста, включая «пограничные» руки: боком к камере, далеко, у края кадра, в полутьме.
2. Остановить запись: скачается `hands-….json`.
3. Разобрать запись:

   ```bash
   node hands/tools/replay-report.js hands-….json
   ```

   Отчёт показывает:
   - гистограммы признаков с отметками порогов;
   - «долину» между сомкнутыми и разомкнутыми пальцами — туда и ставится порог щипка;
   - ленту жестов;
   - счётчики дребезга.

   Чтобы примерить новые пороги без правки кода, добавить `--cfg '{"pinchOn":0.28,"pinchOff":0.45}'`.
4. «⟲ Повтор» на странице проигрывает запись вживую, с курсорами и деталью.

## Что проверено, а что нет

- **Проверено автоматически:** вся логика жестов (синтетика), рендер и HUD в Chromium (программный WebGL), загрузка
  MediaPipe под CSP, путь камеры на поддельной камере Chromium, адаптивный выбор делегата.
- **Замеры.** Это облачный контейнер без видеокарты, 4 ядра, всё считается программно, поэтому числа не про ноутбук:

  | Условие | Время кадра (CPU) |
  |---|---|
  | Сцена неподвижна, воркер | 39 мс |
  | Сцена неподвижна, основной поток | 50 мс |
  | Голограмма анимируется, воркер | ~400 мс (программный рендер отбирает процессор) |

  GPU-делегат через swiftshader медленнее CPU, и адаптивный выбор переключается на CPU. На ноутбуке с видеокартой
  рендер идёт на GPU, а распознавание GPU-делегатом обычно укладывается в 10–20 мс, то есть 30 кадров/с.
  **Это ожидание, не замер.**
- **Не проверено: реальные руки перед камерой.** Пороги выставлены по геометрии кисти и синтетике.
  Где жесты, скорее всего, будут промахиваться (проверить записью):
  - рука ребром к камере: большой и указательный перекрываются в кадре, возможен ложный щипок. Глубина `z`
    учитывается с весом ½, но MediaPipe оценивает её грубо;
  - полусогнутая кисть: между «щипком» и «кулаком» отличается только сгиб указательного (`fistOn 1,20`);
  - «ладонь» с прижатыми пальцами не засчитывается: нужны все 4 пальца прямыми и отведённый большой;
  - быстрые взмахи: смаз кадра, MediaPipe теряет руку. Пропуски до 160 мс перекрываются;
  - перекрещённые руки: сопоставление по положению может перепутать треки в момент пересечения.

## Что понадобится, чтобы перенести на сайт

Ничего из этого не применено, `index.html` и `sw.js` не тронуты.

1. **CSP** (мета-тег в `index.html`): добавить `'wasm-unsafe-eval'` в `script-src`. Без него WebAssembly MediaPipe
   не компилируется. Остальное уже есть:
   - `connect-src 'self'` — загрузка модели и wasm;
   - `worker-src 'self'` — воркер распознавания из файла, `blob:` не нужен;
   - видео с камеры идёт через `srcObject` и `media-src` не требует.

   Мета-CSP страницы на воркер не действует; на GitHub Pages заголовков нет, воркер грузит только свои файлы.
2. **Экспорт из IG3**: в строке `return {P,J,jc,viewer,…}` блока `window.IG3` добавить `CSG,featLines,silLines`
   (сейчас это делает `tools/extract-models.js` при копировании). Либо, как здесь, держать готовую
   геометрию в `v5.js` (326 КБ) и не трогать IG3 вовсе.
3. **Камера в Telegram**: в мини-приложении нужен доступ к камере у WebView (`allow="camera"`). На это сайт не влияет;
   на обычной странице GitHub Pages камера доступна.
4. **`sw.js`**: сейчас он кладёт в кэш `nachert-v121` всё, что загружено с сайта. Значит, после первого открытия
   `hands/` у посетителя закэшируется ~22 МБ (`vision_wasm_internal.wasm` 14 МБ, `hand_landmarker.task` 7,8 МБ).
   Нужно:
   - **не** добавлять эти файлы в `addAll` при установке, иначе каждый посетитель сайта скачает 22 МБ;
   - для `/hands/vendor/` — отдельный кэш `nachert-hands-v1` по схеме «сначала кэш» (файлы неизменны,
     версия — в имени кэша), чтобы он не стирался при каждой смене `C`;
   - поднять версию `C`.
5. **Подключение в интерфейс**: сайт вызывает `IGUI.mountViewer(host, n, opt)`. Голограмма — отдельный компонент:
   `createHolo(canvas, данные)`, `createHud(canvas)`, `createController()`, всё из ES-модулей `hands/`. Для «руки вместо мыши»
   на любом просмотрщике сайта достаточно `gestures.js` + `detector.worker.js`. Контроллер меняет `view.yaw/pit/zoom`,
   а `panX/panY` переводятся в `S.tx/S.ty` (сдвиг; `S.off` у просмотрщика — это положение секущей плоскости, не панорама).
6. **Разбор других вариантов**: `tools/build-v5.js` режет дерево вида `S(U(тело₁, тело₂, …), вырез₁, …)`:
   - части — `S(телоᵢ, …все вырезы)`;
   - пробки — `I(вырез, U(тела))`.

   Так устроены 28 из 30 вариантов. Для варианта 18 и 29 (одно тело) остаются только пробки. Раскладку (`layout`
   в `holo.js`) и подписи (`LABELS` в `hud.js`) каждому варианту нужно задать своими.
7. **Вес**: `vendor/` — 22 МБ, страница без него — около 0,4 МБ. Модель грузится только по кнопке «Включить руки».
