# ТЗ: «Начерт» как игра в мастерство

Техническое задание для ИИ-кодера. Репозиторий: `nachert1830/nachert`.
Цель: собрать в одном сайте лучшие проверенные практики образовательных платформ и игр (раздел 2А — что именно и на каких данных). Человек приходит «на минутку», остаётся на полчаса и уходит, **реально умея больше**, а не просто набрав очков. Механики видеоигр используются как двигатель, а метрика успеха — что человек решает сам через неделю и через месяц.

## 0. Прочитай перед началом (обязательные ограничения)

Сайт уже устроен определённым образом. Ничего из этого не ломать:

1. **Один файл `index.html`**, без сборки, без фреймворков, без npm-зависимостей в рантайме. Весь новый код — внутри него, в стиле существующего кода (ванильный JS, функции `viewXxx(v,r)`, хэш-роутинг `#/...`, хелпер `H(...)` для ссылок, `pageHTML({...})` для страниц).
2. **Хранилище — только `ST.get/ST.set`** (обёртка над `localStorage` с префиксом `nch2_` и запасным `MEM`). Новые ключи — с префиксом `nch2_`, через `ST`. Никаких cookies.
3. **CSP в `<head>`** не расширять без явной необходимости. Новые внешние домены в этапе 1 запрещены.
4. **Яндекс Метрика включается только после согласия** (`nch2_ck === 'y'`). Любая новая отправка данных — только при согласии и только через уже подключённую Метрику (этап 1).
5. **Цветовая политика `docs/color-policy.md` — закон.** Новых цветов не заводить. Роли: синий `--acc` — действие; зелёный `#3a7a55` — «верно/проверка»; бордо `#9b2335` — результат/ошибка; песок — среда; нейтральные — основа. Не больше трёх оттенков на экран. Цвет всегда дублируется формой или подписью. Никаких радужных градиентов, конфетти всех цветов, «казино»-эффектов.
6. **Кошка-маскот (`CAT`, `CATSAY`, `CAT_SPOT`)** — уже есть, использовать её как «спутника» в новых механиках, а не вводить нового персонажа.
7. **Режим владельца и флаги (`FLAGS.on(k)`, страница `#/me`)** — все новые механики сначала выкатываются **за флагом**, видимым только владельцу. Каждый этап — свой флаг (`mastery`, `review`, `quests`, `boss`, `share`).
8. **Тесты:** `node tests/run.js` должен проходить. Новые страницы попадают в обход на ширине телефона (без горизонтальной прокрутки, без ошибок консоли). Для новой логики добавить тесты (см. раздел 9).
9. **Service worker:** при выкладке поднять версию кэша в `sw.js` (`nachert-v68` → `v69` и т.д.).
10. Сайт некоммерческий и неофициальный. Не добавлять ничего, что выглядит как официальная оценка МГТУ.

## 1. Методика: на чём держится «становятся умнее»

Каждая механика ниже обязана опираться хотя бы на один из этих принципов. Если механика их не поддерживает — она не делается.

1. **Извлечение из памяти (retrieval practice).** Вспомнить сложнее, чем перечитать, и поэтому полезнее. Сайт чаще спрашивает, чем показывает.
2. **Интервальное повторение.** Тема возвращается к человеку через 1, 3, 7, 16, 35 дней, пока не станет устойчивой.
3. **Чередование (interleaving).** В повторении задачи разных тем перемешаны: человек учится не только решать, но и **узнавать, какой метод нужен**. Для начерталки это главное умение на РК.
4. **От разобранного примера к самостоятельному (faded worked examples).** Сначала все шаги показаны → потом скрыт последний шаг → потом два → потом решай сам. Плеер уже умеет показывать шаги — нужно научить его прятать.
5. **Генерация до подсказки.** Перед показом шага — вопрос «что строим дальше?» с 2–4 вариантами. Сначала попытка, потом ответ.
6. **Мгновенная и объясняющая обратная связь.** Не «неверно», а «линия связи должна быть ⊥ оси x — ты провёл наклонную». Тесты сайта уже умеют находить такие ошибки (`geometry.js`, `mutate.js`) — переиспользовать категории ошибок.
7. **Мастерство вместо пройденности.** Тема «освоена», только когда решена **сама, без подсказок, на новом варианте, с перерывом во времени**.
8. **Желательные трудности.** Задача должна быть на грани умения (зона «потока»): ~70–85% успешных попыток. Слишком легко — повышаем, слишком тяжело — даём шаг назад.
9. **Метапознание.** Перед ответом человек ставит уверенность («уверен / не уверен»). Уверенная ошибка — самый ценный сигнал, такие задачи возвращаются раньше.

## 2. Игровые аналогии → механики

Принцип: брать из игр **то, что делает игрока лучше** (Dark Souls, Portal, рогалики, Zelda), а не то, что держит его ради удержания (лутбоксы, страх потерять серию).

| Игра | Что затягивает | Механика на «Начерте» |
|---|---|---|
| **Portal** | Новая механика вводится в безопасной комнате, потом комбинируется с прошлыми | Каждая тема: «камера-введение» (1 мини-задача на одну идею) → «камера-комбинация» (вместе с предыдущей темой). |
| **Dark Souls** | Трудно, но честно; смерть учит; прогресс — это навык игрока | Ошибка не наказывается потерей очков. После ошибки — «что пошло не так» + та же задача с новыми данными. Фраза кошки при ошибке: «Так строят многие. Смотри, где линия ушла». |
| **Рогалики (Hades, Slay the Spire)** | Короткие забеги, процедурные уровни, каждый забег чуть иначе | «Забег»: 5 задач по 2–3 минуты, сгенерированных из пула с сидом. Сид в URL — можно скинуть другу тот же забег. |
| **Zelda / метроидвании** | Карта открывается по мере появления умений | «Карта курса»: темы — регионы. Регион «открыт» всегда (порядок не навязываем, как сейчас), но **светится мастерством**: туман → контур → цвет. |
| **Боссы** | Проверка всего, чему научился, в конце зоны | «Босс раздела» = мини-РК: 3 задачи разных тем раздела, без подсказок, на новых вариантах. Победа = раздел освоен. |
| **Speedrun / «призрак»** | Соревнование с собой прошлым | Личный рекорд по каждой задаче: время и число подсказок. «Призрак» — твоя прошлая попытка (сравнение, а не таблица чужих людей). |
| **Strava** | Личные рекорды, недельная сводка | «Неделя»: сколько задач решено сами, какие темы окрепли, что пора повторить. |
| **Duolingo** | Серия дней | Серия дней с **двумя заморозками в запасе** и праздничным экраном на вехах (3, 7, 14, 30 дней) — обе механики Duolingo проверял экспериментами (см. раздел 2А). Плюс мягкая «серия недель» для тех, кто учится не каждый день. Никаких «ты потеряешь серию!» в 23:50. |
| **Pokémon / коллекции** | Собрать всё | «Тетрадь мастера»: 89 задач как карточки. У карточки 3 состояния: разобрана → решена сам → освоена (решена сам повторно через ≥3 дня на новом варианте). |
| **Ачивки Steam** | Скрытые достижения за необычное | Немного (до 15), за **полезное поведение**: «Нашёл 10 подсаженных ошибок», «Решил уверенно и верно 5 подряд», «Вернулся к старой теме через месяц и решил». Никаких ачивок «зашёл 100 раз». |
| **TikTok** | Бесконечная лента, свайп, следующая карточка подобрана под тебя | «Лента» (раздел 4А): вертикальная лента микрозадач по 20–60 секунд, следующую подбирает модель мастерства, лента сама делает паузы. |

### Исследования

| Тема | Что известно | Вывод |
|---|---|---|
| **Геймификация в целом** | Метаанализ Sailer & Homner (2020): эффект на знания g = 0,49, на мотивацию 0,36, на поведение 0,25. В строгих экспериментах устойчив только эффект на знания (g = 0,42); эффекты на мотивацию и поведение незначимы. Сочетание соревнования **с сотрудничеством** работало лучше, чем только соревнование. | Игровые механики оправданы, **только если они встроены в само решение задач**. Соревнование — только вместе с командной целью. |
| **Награды и внутренняя мотивация** | Метаанализ Deci, Koestner & Ryan: ожидаемые материальные награды снижают внутреннюю мотивацию (d = −0,36), особенно «за участие» и «за завершение». Хуже всего — награды по результату, когда максимум получают не все (d = −0,88). Информационная похвала, наоборот, повышает мотивацию у студентов (d = 0,43), а контролирующая — снижает. Неожиданные награды не вредят. | **Не берём:** награды за время, за вход, за «пройденность»; рейтинги, где награду получают только лучшие. **Берём:** обратную связь, объясняющую, что получилось; неожиданные находки в конце забега (не анонсировать заранее). |
| **Проверка вместо перечитывания** | Метаанализы дают средний эффект самопроверки около g = 0,50–0,61, в учебных классах до 0,67. Эффект сильнее, когда после ответа показывают правильный. | Каждая задача — попытка, и только потом — разбор. Правильный ответ показывается всегда после попытки. |
| **Чередование** | В эксперименте Rohrer и коллег с семиклассниками по математике на отложенном тесте через две недели перемешанные задачи решили на 72%, блочные — на 38%. | Забеги, повторение и боссы — всегда перемешанные. Блочная практика — только в «камере-введении» новой темы. |
| **Короткие видео (TikTok)** | В эксперименте с 60 участниками только TikTok (не YouTube и не Twitter) значимо ухудшил выполнение задуманных действий; авторы связывают это с короткими роликами и частым переключением контекста. | Лента — не видео, а задачи, и **внутри одной темы-блока** (не прыгать между темами на каждой карточке). Автопауза каждые 10 карточек. Пассивных роликов в ленте нет. |

### Сводка: как теперь выглядит «рецепт»

1. **Главная метрика** — навыки на уровне ≥3 и доля верных отложенных повторений. Не минуты.
2. **Двигатель** — самопроверка + интервальное повторение + чередование (самые сильные эффекты в исследованиях).
3. **Подача** — как у Brilliant: сначала действие и вопрос, потом метод; 3D и эпюр как то, что можно трогать.
4. **Удержание** — как у Duolingo: серия с заморозками, вехи, короткие занятия; но без давления и без уведомлений.
5. **Социальное** — кооперация плюс мягкое соревнование, никогда — только рейтинг.
6. **Награды** — информационная обратная связь и неожиданные находки; никаких наград «за присутствие».

## 3. Ядро: модель мастерства (этап 1)

### 3.1 Единица — навык, а не страница

Ввести справочник навыков `SKILLS` (≈20–30 штук), привязанный к темам `COURSE` и задачам. Пример:

```js
// id: короткий латинский ключ; topic: id урока из COURSE; tasks: номера задач тетради
const SKILLS=[
  {id:'link',   t:'Линии связи и координаты точки',  topic:1, tasks:[1,2,3]},
  {id:'compete',t:'Конкурирующие точки и видимость',  topic:2, tasks:[...]},
  {id:'hf',     t:'Горизонталь и фронталь плоскости', topic:5, tasks:[...]},
  {id:'replace',t:'Замена плоскостей проекций',       topic:7, tasks:[...]},
  // ...
];
```

Заполнить по реальному `COURSE` и задачам тетради. Если навык задачи неочевиден — брать тему урока, к которому задача привязана в `tasksOf(l.id)`.

### 3.2 Уровни мастерства навыка (0–4)

| Уровень | Название | Как получить | Вид |
|---|---|---|---|
| 0 | Не начато | — | контур, серый |
| 1 | Знаком | Прочитан урок или разобрана задача (`taskState=1`) | контур синий |
| 2 | Получается | 1 задача решена сам без подсказок | заливка синяя 40% |
| 3 | Умею | 2 решены сам, одна из них — новый вариант из тренажёра | заливка синяя |
| 4 | Освоено | Подтверждено повторением через ≥3 дня **или** победой над боссом | заливка + зелёная галочка ✓ |

Уровень **может опуститься на один шаг**, если повторение провалено. Это честно и мотивирует вернуться. Падение не сопровождается красным и тревожными текстами — просто «Навык ослаб, повторим?».

### 3.3 Попытка (событие)

Каждое решение записывается как попытка:

```js
// ST 'att' — массив, хранить последние 2000, старые сворачивать в агрегаты
{s:'hf', task:47, seed:1234, mode:'build'|'var'|'bug'|'path'|'review'|'boss',
 ok:true, hints:0, conf:1 /*0 не уверен,1 уверен*/, ms:142000, d:20381 /*день от эпохи*/}
```

### 3.4 Интервальное повторение

Упрощённая модель в духе FSRS (раздел 2А). Для каждого навыка: `ST 'srs'` → `{[skillId]:{lvl, S, D, last, due}}`.
- `S` — стабильность в днях (за сколько дней вероятность вспомнить падает до 90%). Старт: 1 день.
- `D` — трудность навыка 1–10. Старт: 5; вычисляется из доли ошибок по навыку.
- Вероятность вспомнить сейчас: `R = (1 + t/(9*S))^-1`, где `t` — дней с последней попытки.
- Целевая доля запоминания `RET = 0.9` (в настройках можно 0.8–0.95).
- `due` — день, когда `R` опустится до `RET`; при `RET=0.9` это `last + S`.
- После попытки:
  - верно без подсказок → `S = S * (1 + 2.2 * (11-D)/10 * (1-R+0.1))` (чем ближе к забыванию было, тем больше рост);
  - верно с подсказками → `S = S * 1.2`;
  - неверно → `S = max(1, S * 0.3)`, `D = min(10, D+1)`; уверенная ошибка → `S = 1`.
- Коэффициенты — стартовые, вынести в константы. На этапе 2, когда накопятся обезличенные данные, их можно подогнать по реальной истории (как это делает FSRS).
- Тест: на синтетической истории модель даёт возрастающие интервалы примерно 1 → 3 → 7 → 16 → 35 дней при сплошь верных ответах.

### 3.5 Адаптивная сложность

Для навыка считать долю успеха по последним 6 попыткам.
- `> 85%` → следующая задача без шагов-подсказок / с бóльшим сокрытием шагов.
- `70–85%` → оставить.
- `< 70%` → включить «затухающий пример» с меньшим числом скрытых шагов, предложить урок-шпаргалку.

### 3.6 Перестроить прогресс на главной

Сейчас `renderHProg()` считает «пройдено шагов». Заменить (за флагом `mastery`) на:
- кольцо = средний уровень мастерства по навыкам / 4;
- подпись: «Освоено 6 навыков из 24 · 3 пора повторить».

Старый процент оставить как всплывающую подсказку для совместимости.

## 4. Главный цикл занятия (этап 1)

### 4.1 Кнопка «Занятие на 10 минут» на главной

Над «Вы остановились» — одна главная синяя кнопка. Нажатие собирает **забег**:

1. Сначала навыки с наступившим `due` (повторение), до 2 задач.
2. Затем 1–2 задачи из навыка «на грани» (уровень 1–2).
3. 1 задача из нового навыка, если человек готов (предыдущий навык ≥2).
4. Задачи **перемешаны по темам** (чередование).
5. Всего 4–6 задач, оценка времени ~10 мин.

Маршрут: `#/run/<seed>`. Сид детерминирует состав забега, чтобы можно было поделиться.

### 4.2 Шаг задачи в забеге

1. Показ условия и чертежа «Дано».
2. Вопрос «Что строим первым?» — 3 варианта (правильный + 2 правдоподобных из соседних методов). Это тренирует **узнавание метода**.
3. Режим решения:
   - уровень навыка 0–1: плеер со всеми шагами, но перед каждым шагом — «что дальше?»;
   - уровень 2: скрыт последний шаг (`build` из тренажёра);
   - уровень 3+: «Построй сам» целиком или «Найди ошибку».
4. Перед проверкой — переключатель уверенности: «Уверен» / «Не уверен».
5. Обратная связь сразу: что верно, где ошибка, объяснение из текста шага.
6. Подсказка доступна всегда, но фиксируется (`hints+1`). Подсказка — не наказание, просто влияет на рост мастерства.

### 4.3 Конец забега — экран итогов

- Какие навыки выросли (кольца анимированно дорастают, 400 мс, `prefers-reduced-motion` — без анимации).
- «Неожиданная находка» (переменное вознаграждение, но **полезное**): случайно один из пунктов — интересный факт по теме, «призрак» прошлой попытки (было 4:10 → стало 2:35), открытая ачивка, или «ты готов к боссу раздела».
- Одна кнопка «Ещё забег» и одна неприметная «Хватит на сегодня» — **обе одинаково заметны** (не тёмный паттерн). Кошка: «Мозг закрепляет во сне. Возвращайся завтра».
- Если человек сделал 3 забега подряд — мягко предложить перерыв.

## 4А. «Лента» — учебный аналог TikTok (этап 1, флаг `feed`)

Маршрут `#/feed`. На телефоне — вертикальная лента на весь экран, листается свайпом вверх; на компьютере — колёсиком и стрелками.

**Карточка** — одна микрозадача на 20–60 секунд, без длинного текста:
- «Где ошибка?» — чертёж из тренажёра «Найди ошибку», нажать на место ошибки;
- «Какой метод?» — условие и 3 варианта метода (тренирует узнавание);
- «Что строим дальше?» — чертёж на шаге k, 3 варианта шага k+1;
- «Покрути» — 3D-модель: повернуть так, чтобы точка стала конкурирующей / плоскость стала проецирующей;
- «Верно или нет?» — утверждение по теории (из `tests/theory.js` есть шаблоны неверных формулировок).

**Подбор следующей карточки** — модель мастерства, а не алгоритм удержания: навыки с наступившим `due` → навыки «на грани» (успех 70–85%) → изредка (1 из 8) карточка из нового навыка. Карточки идут **блоками по 5 в одной теме**, затем смена темы — чтобы не было частого переключения контекста (раздел 2А).

**Правила:**
- Ответ — обязательно действие (нажать, выбрать, повернуть). Пассивных карточек нет.
- После ответа — мгновенная обратная связь на той же карточке, 1–2 строки, плюс «Подробнее» (открывает полный разбор задачи).
- Каждые 10 карточек — **пауза-итог**: что получилось, какой навык подрос, кнопки «Ещё 10» и «Хватит» одинаковой заметности.
- После 30 карточек подряд — кошка предлагает перерыв; лента продолжается только по явному нажатию.
- Нет автопроигрывания звука, нет бесконечной прокрутки без пауз.
- Каждая карточка — это попытка в `att` (раздел 3.3), лента двигает мастерство так же, как забег.
- Генерация карточек — из существующих данных (`WB3.tasks`, шаги плеера, генератор вариантов, мутации ошибок). Новые чертежи вручную не рисовать.

## 5. Награды (этап 1–2)

### 5.1 Что награждаем

Награда идёт за **усилие и рост**, не за время на сайте:
- решено сам (без подсказок) — основная валюта;
- решено с первой попытки после ошибки на прошлой неделе;
- повторение в срок;
- найдена подсаженная ошибка;
- уверенно и верно (калибровка).

### 5.2 Что видит человек

1. **Карта курса с туманом** (вместо/поверх сетки тем `ngPath`): регионы-темы светятся по уровню мастерства. Цвета — только роли из цветовой политики.
2. **Тетрадь мастера** — 89 карточек задач, 3 состояния. Освоенная карточка получает рамку и номер «ранга».
3. **Ранги** (по числу освоенных навыков, а не очков): Чертёжник → Конструктор → Инженер-геометр → Мастер эпюра. 4 ранга, без бесконечной гонки.
4. **Достижения** (≤15), часть скрыты до получения. Список в `ACH` с условием-функцией от `att` и `srs`.
5. **Недельная сводка** (`#/week`): сколько решено сам, какие навыки окрепли, рекорды, что повторить. Можно сохранить картинкой.
6. **Серия дней**: день засчитан, если решена сам хотя бы одна задача или карточка ленты. В запасе до **2 заморозок**: одна начисляется за каждые 7 дней серии, расходуется автоматически за пропущенный день. Экран вехи на 3, 7, 14, 30, 100 дней (в цветах политики, ≤400 мс). Без push-уведомлений.
7. **Серия недель** (для тех, кто не учится каждый день): неделя засчитана, если ≥3 дня с занятиями. Показывается, когда серия дней прервалась, — чтобы не обнулять ощущение прогресса.
8. **Возвращение после перерыва**: человек, не заходивший 7+ дней, видит тёплый экран без упрёков и короткий забег-повторение на 5 минут, а не список «просроченных» тем.
9. **Неожиданные находки** не анонсируются заранее и не выдаются за время на сайте: только в конце забега или на паузе ленты (раздел 2А: неожиданные награды не снижают внутреннюю мотивацию).

### 5.3 Чего НЕ делать (тёмные паттерны — запрещено)

- Нет потери прогресса за пропуск дней.
- Нет уведомлений и всплывашек, давящих на страх и стыд.
- Нет таймеров «осталось 5 минут, чтобы не потерять серию».
- Нет приглушённой кнопки «выйти» / «хватит».
- Нет случайных наград без связи с учёбой (лутбоксы, рулетка).
- Нет общих публичных рейтингов «ты на 3412 месте».
- Нет очков за время, проведённое на сайте.

## 6. Боссы и экзамен (этап 2)

- **Босс раздела** (`#/boss/<part>`): 3 задачи разных тем раздела на новых вариантах, без подсказок и без «что дальше?». Ограничения времени нет (время только записывается). Победа (3/3 или 2/3 с исправлением) → навыки раздела получают уровень 4.
- **Финальный босс — «Репетиция РК»**: 4–5 задач из разных разделов, перемешанные. Итог: какие навыки держатся, какие проседают, прямые ссылки на повторение.
- Босс открывается, когда ≥70% навыков раздела на уровне 3 — но **можно попробовать раньше** («Рискнуть»). Проигрыш = подробный разбор, без штрафа.

## 7. Социальная часть без аккаунтов и личных данных

Цель «фейсбук образования» — достигается через **совместные действия**, а не профили с фото. Делится в два этапа.

### 7.1 Этап 1 — без сервера (работает на GitHub Pages как есть)

1. **Поделиться забегом.** `#/run/<seed>` — друг проходит тот же набор задач. В конце — сравнение «твоё время/подсказки» vs «его», если он прислал свою ссылку-результат.
2. **Ссылка-вызов.** `#/duel/<seed>/<результат>` — результат кодируется в URL (время, число подсказок, верно/неверно по задачам; без имени, ник по желанию до 16 символов, хранится только в URL). Получатель видит «Тебя вызвали: 5 задач, 6:40, 1 подсказка. Сможешь лучше?».
3. **Карточка достижения** для соцсетей: SVG → PNG (уже есть механизм `FX.shareMenu` и экспорта эпюра). Без личных данных, только навык/ранг/рисунок.
4. **Перенос прогресса между устройствами — код прогресса.** Кнопка «Перенести на другое устройство»: состояние (`wb3`, `srs`, агрегаты `att`, `ach`) сжимается (`CompressionStream('deflate')` + base64url) и показывается как код + QR. На другом устройстве — «Вставить код». Ни сервера, ни email. Плюс экспорт/импорт файлом `.nachert.json`.

### 7.2 Этап 2 — минимальный сервер (отдельное решение владельца)

Только если владелец решит. Требования:
- Хостинг — бессерверная функция (например Cloudflare Workers + D1, или Supabase). Домен добавляется в CSP `connect-src`.
- **Нет регистрации, email, телефона, имён.** Профиль = случайный ключ, сгенерированный в браузере (`crypto.getRandomValues`, 128 бит), + псевдоним по выбору. Потерял ключ — потерял профиль (честно предупредить; показать «фразу восстановления» из 6 слов).
- Сервер не пишет IP в логи, не ставит cookies.
- **Учебные группы по ссылке-приглашению** (`#/g/<код>`): группа видит **общий** прогресс («группа освоила 63% навыков раздела 2»), недельную «общую цель» («вместе решить 100 задач сами») и анонимную ленту «кто-то из группы только что победил босса раздела 3». Индивидуальные рейтинги — только если группа включила (по умолчанию выключено).
- **Кооперативные лиги** (вместо лиг Duolingo в чистом виде — раздел 2А). Неделя, группа ~20 человек со схожим уровнем. Две части:
  - **общая цель лиги** («вместе 150 навыков подняли на уровень») — если выполнена, бонус получают **все**;
  - **личная часть** — сравнение по «решено сам» и «вовремя повторено», а не по минутам. Повышение в следующую лигу получает не топ-3, а каждый, кто выполнил свою недельную цель (30 мин и 2 навыка). Понижения нет.
  - Участие в лигах — по желанию, по умолчанию выключено.
- **Режим преподавателя:** создаёт группу, видит **сводку по навыкам группы** (где все проседают), а не оценки отдельных людей. Это ценность для кафедры и семинаристов.
- Правовая часть до запуска: проверить с юристом соответствие 152-ФЗ (псевдонимный идентификатор может считаться персональными данными, если его можно связать с человеком). Обновить `#/privacy`.

## 8. Польза для проекта без сбора личных данных

Что владелец сайта получает, не узнавая, кто конкретно учится:

1. **Карта трудностей курса (главное).** Обезличенные события «задача 47, шаг 5, ошибка категории "линия связи"». Агрегат показывает, какие шаги ломают больше всего людей → какие объяснения переписать. Это делает сайт лучше быстрее любого опроса.
   - Этап 1: только при согласии (`nch2_ck==='y'`), через уже подключённую Метрику: `ym(ID,'reachGoal','step_fail',{task:47,step:5,cat:'link'})` и `params` без идентификаторов. Не чаще 1 события на попытку, батчем в конце задачи. Никаких текстов ответов, никаких сидов, по которым можно что-то склеить.
   - Добавить в `#/privacy` точный список отправляемых полей.
2. **Метрики качества методики**, чтобы доказывать, что сайт работает: доля «освоено» через 7/30 дней, доля верных повторений в срок, процент побед над боссом с первой попытки. Считается в браузере, отправляется (при согласии) только как агрегированные числа по навыку, например раз в неделю.
3. **Публичная страница «Что мы узнали»** (`#/about/insights`): самые трудные шаги курса и как их переписали. Это репутация проекта, материал для статьи/доклада/диплома, аргумент для кафедры.
4. **Открытый обезличенный датасет** трудностей (раз в семестр, только агрегаты) — интересен исследователям обучения.
5. **Поддержка без данных:** кнопка «Поддержать проект» на донат-платформу (только ссылка, без скриптов и пикселей). Показывать на экране итогов недели, не чаще раза в месяц, без давления.
6. **Партнёрство с преподавателями** (этап 2): режим группы как бесплатный инструмент для семинаров → рост аудитории через кафедры, не через рекламу.

Запрещено: продавать или передавать данные, подключать рекламные сети, ставить сторонние пиксели, сохранять тексты ответов, fingerprinting устройства.

## 12. Этапы и критерии приёмки

### Этап 1 — ядро (без сервера), флаги `mastery`, `review`, `quests`, `feed`

## 13. Как мерить, что работает

Встроить (локально, у владельца в `#/me`) и, при согласии, агрегировать:
- **Удержание знаний:** доля повторений, решённых верно в срок через 7 и 30 дней. Цель — ≥75%.
- **Самостоятельность:** доля задач, решённых без подсказок, растёт неделя к неделе.
- **Калибровка:** уверенные ошибки со временем редеют.
- **Возвращаемость:** доля людей с серией ≥2 недель (только агрегат).

Если вовлечённость растёт, а удержание знаний — нет, механика вредная и убирается. Главная метрика — знание, не минуты.

### Расхождения с ТЗ и почему

1. **Коэффициенты модели повторения (3.4).** С формулой роста из ТЗ при повторении в срок (R = 0,9) стабильность растёт лишь в 1,26 раза, и интервалы 1 → 3 → 7 → 16 → 35 не получаются. Формула оставлена, коэффициент роста подобран (`K.GROW = 16,7`), и добавлено затухание `S^−0,2`, как в FSRS. Итог при сплошь верных ответах: 1 → 3 → 8 → 18 → 39 дней. Повторное решение в тот же день стабильность не меняет: это зубрёжка, а не повторение. Трудность D растёт на 1 при ошибке, при верном ответе не меняется.
2. **Сид забега.** Чтобы друг получил тот же забег, что и автор (а состав зависит от личного прогресса), сид — это сам состав: `#/run/12.47.5.63-k3f9` (номера задач + случайное число для вариантов данных). Просто число (`#/run/1234`) собирает смешанный забег из курса по генератору. В обоих случаях один сид — один состав. Режим решения каждой задачи подбирается под уровень того, кто решает.
3. **Уверенность** спрашивается один раз на задачу — на вопросе «С чего начать?» (две кнопки: «Ответить: уверен» / «Ответить: не уверен»), а не перед каждой проверкой.
4. **«Решай сам» (уровень 3+)** — решение на бумаге с самопроверкой «Совпало / Не совпало», как в Anki. «Построй сам» с отметкой точек остаётся за флагом `build`: на телефоне он неточен.
5. **Лента:** «1 из 8 карточек из нового навыка» сделано как «новый навык в среднем у каждого восьмого блока из 5 карточек» — иначе ломаются блоки по 5 карточек одной темы. Карточки «Покрути» (3D) пока нет.
6. **Этап 2 не делался:** боссы, сервер, группы, лиги, `#/about/insights`. Ранги считаются по навыкам на уровне «Умею» и выше (0 / 6 / 12 / 18 из 22).
7. **События трудностей:** при согласии через уже подключённую Метрику уходит одна цель `step_fail` на неудачную попытку с полями `task`, `step`, `cat`. Список полей добавлен в `#/privacy`.
