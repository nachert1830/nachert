# Обязательная проверка перед слиянием — как включить (для владельца)

Проверка сайта (`.github/workflows/check.yml`) на каждом PR выдаёт одну итоговую отметку — **«Итог проверки»**
(в списке проверок PR она видна как `Проверка сайта / Итог проверки`). Она зелёная, только если:

- карта влияния сама прошла свой тест (`tests/impact.test.js`);
- все выбранные блоки проверки сайта и тесты сервера прошли;
- задание законно пропущено только тогда, когда план так решил: блоков нет, если изменены одни документы (`*.md`, `docs/**`),
  тестов сервера нет, если правка их не касается. Красное или отменённое задание делает итог красным.

Пока эта отметка не обязательна, GitHub разрешает слить PR с красной или незаконченной проверкой.
Ниже — как сделать её обязательной. Это делается один раз, в настройках репозитория, только владельцем.

## 1. Правило для ветки main

1. Открой репозиторий на GitHub → **Settings** → слева **Rules** → **Rulesets**.
2. **New ruleset** → **New branch ruleset**.
3. **Ruleset name**: `main под проверкой`. **Enforcement status**: `Active`.
4. **Target branches** → **Add target** → **Include default branch** (это `main`).
5. В разделе **Rules** включи:
   - **Restrict deletions** и **Block force pushes** — историю main нельзя переписать или удалить;
   - **Require a pull request before merging** — правка попадает в main только через PR.
     **Required approvals**: `0` (ты работаешь один; ревью не нужно, нужна проверка);
   - **Require status checks to pass** → **Add checks** → введи `Итог проверки` и выбери его (источник — GitHub Actions).
     Отметка появляется в поиске после того, как проверка хотя бы раз прошла с этим заданием, — то есть после первого PR
     с новым `check.yml`. Если её ещё нет в списке, открой любой PR, дождись проверки и вернись сюда.
   - **Require branches to be up to date before merging** — рекомендую включить: тогда PR проверяется поверх свежего main,
     и две правки, каждая зелёная по отдельности, не сломают сайт вместе. Минус — после каждого слияния остальные PR надо
     обновить кнопкой **Update branch** (это делает и Цех, начиная задачу со свежего main).
6. **Bypass list** оставь пустым — тогда и твои собственные слияния идут через проверку. Это и есть цель.
7. **Create**.

## 2. Автослияние для Цеха

**Settings** → **General** → раздел **Pull Requests** → включи **Allow auto-merge**.

Цех (`hq-work.yml`) сливает PR командой `gh pr merge`; если обязательная проверка ещё идёт, он ставит PR в очередь
(`gh pr merge --auto`), и GitHub сам сольёт его, когда «Итог проверки» станет зелёным. Без этой настройки Цех напишет
«влить не вышло» и PR останется ждать твоего нажатия.

## 3. Кто сейчас пишет в main напрямую

Правило из п. 1 запрещает прямые пуши в main. Сейчас напрямую пишут:

| Задание | Что пишет | Что делать |
|---|---|---|
| `views.yml` | счётчик просмотров `views.json` | добавить GitHub Actions в Bypass list правила (если в списке есть такой пункт) или перевести на PR |
| `club.yml`, `scan-deploy.yml`, `ceo-deploy.yml` | адрес облачной функции в `lk/config.js`, `lk/scan/config.js`, `ceo/config.js` после развёртывания | то же |
| `hq-work.yml`, откат | `git revert` выкатки и пуш в main | то же; откат и так прогоняет задетые блоки перед пушем |

Если GitHub Actions нельзя добавить в Bypass list, эти задания после включения правила будут падать на пуше — это видно
в Actions сразу. Тогда их нужно перевести на PR (пуш в ветку + `gh pr create` + `gh pr merge --auto`): напиши мне,
сделаю отдельной правкой. Обходить правило правами администратора не нужно.

## 4. Как убедиться, что работает

1. Открой PR, который меняет любой файл кроме документации. В списке проверок должны быть `Что задето` (plan),
   блоки проверки и `Итог проверки`; кнопка **Merge** серая, пока `Итог проверки` не зелёный.
2. PR только с правкой `*.md` — `Итог проверки` зелёный через ~1 минуту (блоки законно пропущены).
3. Новый коммит в PR отменяет устаревшую проверку этого PR. Проверки `main` не отменяются никогда: каждый коммит main
   получает свою полную проверку.

## Почему именно так

- Одна итоговая отметка вместо списка всех заданий: набор блоков на каждом PR свой (карта влияния), а обязательной
  можно сделать только отметку, которая есть всегда. Задание `gate` выполняется всегда (`if: always()`) и само решает,
  законен ли пропуск.
- Раньше пропуск задания `check` (карта влияния выбрала «ничего») GitHub засчитывал как успех — так правки уходили в main
  непроверенными. Теперь «ничего» — только для документов, а любой файл вне карты влияния ведёт к полной проверке.
