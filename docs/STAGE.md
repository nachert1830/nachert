# Тестовая версия сайта

Все изменения сначала попадают в ветку `stage` и публикуются в секретной папке `nachert1830.ru/<STAGE_PATH>/`.
Её проверяют глазами, и только потом изменения сливаются в `main`, на nachert1830.ru.

```
рабочая ветка → PR в stage → «Проверка сайта» → тестовая версия (1–2 мин) → прокликали → PR stage → main → nachert1830.ru
```

Оба адреса публикует `.github/workflows/pages.yml`: корень сайта берётся из `main`, секретная папка из `stage`.
Тестовую копию подготавливает `.github/scripts/stage.js`. Ветка `stage` в репозитории при этом не меняется, а в копии:

- все страницы закрыты от поисковиков (`noindex`), на главной в углу плашка «ТЕСТ · коммит»;
- Метрика, Google и GoatCounter заблокированы: тестовые заходы не попадают в статистику и в счётчик просмотров;
- у service worker'ов свои кэши (`stage-…`), поэтому тестовая и настоящая версии не стирают кэш друг друга.

## Что тестовая версия не скрывает

- **Адрес — это и есть защита.** Ссылок на папку нигде нет, поисковики её не индексируют, но кто узнал адрес, тот
  откроет. Поэтому имя папки хранится в секрете репозитория, а не в коде: репозиторий открытый.
- **Хранилище браузера общее с nachert1830.ru** (тот же адрес сайта). Прогресс, тема и согласие на cookie на тестовой
  версии те же, что на настоящей. Новый код, который меняет формат сохранённых данных, проверяйте в отдельном профиле
  браузера или в окне инкогнито.
- **Кабинет (`/lk/`) на тестовой версии работает с настоящим сервером и настоящими данными.** После входа
  Яндекс ID возвращает на nachert1830.ru/lk/. Отдельного тестового сервера пока нет.

## Настройка (один раз)

1. **Settings → Pages → Build and deployment → Source: «GitHub Actions».** Сайт продолжает открываться: до первой
   публикации нового способа остаётся прежняя версия.
2. **Settings → Secrets and variables → Actions → New repository secret:** `STAGE_PATH` — имя секретной папки
   (латиница, цифры, `-`, `_`; например `t-` и 10 случайных символов).
3. **Ветка `stage`** — создаётся из `main`.
4. **Actions → «Публикация сайта» → Run workflow** (ветка `main`): публикует оба адреса сразу.
5. Желательно: **Settings → Rules → Rulesets** для `main` — «Require a pull request» и «Require status checks: Проверка сайта»,
   чтобы на nachert1830.ru не попадало ничего мимо проверки.

Без секрета или без ветки `stage` публикуется только основной сайт (в журнале — предупреждение).
Сменить адрес тестовой версии — поменять секрет и запустить «Публикация сайта»: старая папка исчезнет.
