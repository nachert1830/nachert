# ИИ-тренер: фундамент без модели

Принцип (отчёт-исследование, §3.1): **ядро говорит правду, автомат управляет, модель только формулирует.**
Модель (когда её подключат) видит только текущую ступень подсказки и её словарь; ответа она не знает, поэтому выдать его не может.
Здесь — всё, что работает без модели и уже проверяется тестами.

| Файл | Что это |
|---|---|
| `tutor/passport.schema.json` | JSON-схема паспорта шага |
| `tutor/passport.js` | `TUTOR_PASSPORT` — генератор паспорта из ядра (чертёж шага, текст и обоснование автора, библиотеки ошибок) |
| `tutor/collect.js` | `TUTOR_COLLECT` — паспорта всех шагов: тетрадь (`wb`), варианты ДЗ (`dz`), ИГ (`ig`) |
| `tutor/ladder.js` | `TUTOR_LADDER` — автомат лестницы подсказок Р0–Р4 |
| `tutor/lint.js` | `TUTOR_LINT` — линтер утверждений и детектор секретов |
| `tutor/schema-check.js` | проверка JSON по схеме без зависимостей |
| `tutor/index.html` | тестовая страница «Тренер без ИИ» (`/tutor/`, noindex, ссылок с сайта нет) |
| `kernel/stepview.js` | `STEPVIEW` — разбор шага на подшаги, опоры и подписи (общий с плеером, часть 1) |
| `tests/tutor.js` | тесты (блок `tutor` в `node tests/run.js`); `--coverage` пишет `docs/TUTOR-COVERAGE.md` |

Все файлы работают и в браузере, и в Node (кроме `collect.js` — ему нужны задачи сайта `WB3`, `DZR`, `GEN`).

## Паспорт шага

Идентификатор: `wb.46.s2` (задача тетради 46, шаг 2), `wb.45.б.s3` (пункт б), `dz.ng2.v14.s3` (ДЗ №2, вариант 14),
`ig.ig4.v7.s2` (ИГ, ДЗ №4). Пример (сокращён):

```json
{ "v": 1, "id": "wb.46.s2", "src": {"kind":"wb","task":"46","part":0,"step":2},
  "type": "intersect", "title": "Точка 5 = DF ∩ (ABC)", "goal": "Точка 5 = DF ∩ (ABC)",
  "why": {"text": "1 и 2 лежат и в γ₁, и в (ABC), значит, 12 = γ₁ ∩ (ABC)…", "src": "wb.why"},
  "entities": ["A","B","C","D","E","F","1","2","5", "…"],
  "labels": {"known": ["A″","A′","…","1″","2″","h₀γ₁"], "new": ["1′","2′","5′","5″"], "future": ["3″","4″","6′","…"], "general": ["x"]},
  "facts": [{"id":"F6","rel":"perp","args":["1″","1′","x"],"text":"линия связи 1″1′ ⟂ x","src":"kernel","verified":true,"res":0,"rung":3}, "…"],
  "secrets": {"labels": ["5′","5″","3″","…"], "entities": ["5","3","…"], "numbers": true, "values": []},
  "rungs": [
    {"k":0,"name":"вопрос","text":"Какие две линии должны пересечься, чтобы получилась нужная точка?","src":"template:intersect","labels":["…"]},
    {"k":1,"name":"приём","text":"Общая точка двух линий лежит на обеих сразу — на каждой проекции.","src":"template:intersect","labels":["…"]},
    {"k":2,"name":"объект","text":"Опора этого шага — 1″, 2″.","src":"template:support","labels":["…"]},
    {"k":3,"name":"действие","text":"Перенеси 1′ по линии связи из 1″ до C′A′. Перенеси 2′ по линии связи из 2″ до B′C′.","src":"stepview","labels":["…"]},
    {"k":4,"name":"пример","text":"Посмотри этот же шаг на соседнем варианте, потом сделай на своём.","src":"neighbor","labels":["…"],"neighbor":{"id":"wb.46.s2~gen101","kind":"gen","seed":101}} ],
  "mistakes": [{"id":"cp46.12-swap","what":"Точки 1′ и 2′ перенесены не на те стороны…","detect":"core/cp46.js: judge() — …","src":"core/cp46.js"}, "…"],
  "key_view": {"look":"вдоль одной из пересекающихся линий","why":"видно, что точка лежит на обеих","target":"1″"},
  "topics": ["m4","m5"], "todo": [] }
```

| Поле | Откуда | Как заполняется |
|---|---|---|
| `type` | заголовок, затем текст шага | 14 типов: анализ, видимость, замена, вращение, посредник, натуральная величина, перпендикуляр, линия уровня, параллельность, пересечение, след, линия связи, фигура, построение |
| `goal` | заголовок шага автора | как есть; это цель шага, её видит ученик на подсказке «что делаем» |
| `why` | `step.why` (тетрадь) или «Почему так?» (`principle`, ДЗ) | ссылки «(вопрос 14)» убраны |
| `labels` | чертёж ядра | `known` — подписи условия и прошлых шагов; `new` — этого шага; `future` — будущих шагов |
| `facts` | чертёж ядра + утверждения текста шага (`X ∥ Y`, `X ⟂ Y`, `X ∈ Y`) | каждый проверен по координатам (`verifyFact`); неподтверждённое ядром утверждение текста остаётся с `verified:false` и разрешённым не считается; `rung` — с какой ступени факт можно называть |
| `secrets` | чертёж ядра | все будущие метки и искомое этого шага (элементы цвета ответа); сущность секретна, если все её проекции секретны; любые числа запрещены |
| `rungs[0]` вопрос | шаблон по типу шага | одна фраза, один вопрос, только известные метки |
| `rungs[1]` приём | обоснование автора, если оно проходит линтер на Р1; иначе шаблон по типу | `src` говорит, откуда текст |
| `rungs[2]` объект | опоры шага (`STEPVIEW`) + разрешённый факт | что уже построено и понадобится; новые линии шага можно назвать |
| `rungs[3]` действие | подшаги `STEPVIEW` повелительно | «Отметь 1′ там, где пересекаются…», искомое — словами («искомую точку») |
| `rungs[4]` пример | соседний вариант | тетрадь — вариант генератора `GEN` (если задача в `GEN_OK` и число шагов совпало); ДЗ — ближайший вариант того же типа |
| `mistakes` | по типу шага: общие (GYM «найди ошибку», ядро), `core/cp46.js`, `core/cp47.js`, ловушки подготовки (`prep/`) | `detect` — чем ловит ядро; где программы построения нет — `TODO: …` |
| `key_view` | по типу шага | куда смотреть в 3D, чтобы увидеть главное (посредник схлопывается в линию и т. п.) |
| `topics` | `kernel/prep.js` | темы, закрывающие задачу/ДЗ, отобранные по типу шага |
| `todo` | генератор | чего нет и почему — без выдумок |

Словарь ступени (`rungs[k].labels`): Р0–Р1 — известное; Р2 — плюс новые линии шага; Р3 — плюс все новые несекретные метки;
Р4 — всё. Модель получает `rungs[≤k]`, `facts` с `rung ≤ k` и словарь, **никогда** — `secrets` (их получает только линтер).

## Автомат лестницы (`tutor/ladder.js`)

```
попытка ──(ошибка | 60 с | «помоги»)──▶ Р0 ──▶ Р1 ──▶ Р2 ──▶ Р3 ──(2 ошибки на Р3 | просьба после попытки)──▶ Р4 (соседний вариант)
   Р0…Р2 → следующая: новая ошибка или 45 с без действий;  «дальше» без попытки — повтор той же ступени
   верно на любой ступени → шаг засчитан; если брал Р2+, сначала вопрос «почему так?»
```

- Ошибка из библиотеки паспорта в первый раз — обратная связь (`feedback`) без роста ступени; повтор той же ошибки — как обычная.
- Время ведёт только до Р3; к примеру — только ошибки или просьба после попытки.
- Р4 всегда ссылается на **соседний** вариант; на ошибки после примера автомат отвечает повтором — свой вариант за ученика не решается.
- После примера (`example_seen`) — «теперь на своём»; верное действие → самообъяснение → шаг засчитан.
- Перед РК (`compressed`) лестница сжата: Р0 → Р2 → Р4.
- `session()`: три шага подряд с Р4 — предложить тему-опору (`passport.topics[0]`).

## Линтер (`tutor/lint.js`)

`lint(text, passport, rung)` → `{ok, errors}`. Отказ — коды:

| Код | Правило |
|---|---|
| `LEN`, `Q2` | ≤ 320 символов, не больше одного вопроса |
| `LABEL` | метка не из словаря задачи (разбор — самым длинным совпадением со словарём) |
| `RUNG` | метка есть, но на этой ступени ещё не разрешена |
| `SECRET` | секретная метка или сущность до Р4 |
| `NUM`, `UNIT` | любое число (кроме номеров точек из словаря), «мм», «°», «градус» |
| `REL` | утвердительное отношение (∥, ⟂, ∈, пересекается, натуральная, видимая…) с метками шага без разрешённого факта той же ступени; общее правило без меток — можно |
| `YESNO` | да/нет-вопрос о гипотезе («правда ли…», «не лежит ли…», «ведь…») — так ответ выпытывают по частям |
| `ASK`, `PRAISE` | «понятно?»; похвала личности |

Ложное срабатывание безопасно: берётся более сухой шаблон.

## Тесты

`node tests/tutor.js` (в общем прогоне — блок `tutor`): 57 сценариев автомата, 156 примеров линтера (48 верных, 108 с
нарушениями, включая попытки вытащить ответ по-английски, через «base64» и «игнорируй правила»), паспорт каждого шага тетради
и каждого варианта ДЗ по начерту — схема, линтер всех Р0–Р3, независимая проверка секретов подстрокой, повторная проверка
каждого разрешённого факта по координатам, Р4 ≠ свой вариант. Карта покрытия — `node tests/tutor.js --coverage`.

## Что дальше (по отчёту-исследованию, §7)

1. Наполнить методику по `docs/TUTOR-COVERAGE.md`: обоснования, ракурсы, ошибки с распознаванием.
2. Проактивный пузырь у места ошибки в «Решаю сам» (события `action` — от проверки построения ядром).
3. Только потом — модель: парсер реплики и тренер получают паспорт ступени, ответ проходит `TUTOR_LINT`.
