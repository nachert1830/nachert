# Разведка репозитория (этап 0)

Как устроен сайт «Начерт» и его автоматическая проверка — для того, кто будет её менять.

## Сайт

- **Один файл `index.html`** (≈ 30 тыс. строк): разметка, стили и весь код, без сборки. Хостинг — GitHub Pages
  (`CNAME`, `.nojekyll`), офлайн-кэш — `sw.js`.
- **Задачи рабочей тетради** — программы построения: каждая задача — блок `(function(){ … WB3.add({…}) })();`.
  Исходные точки заданы числами (мм тетради), остальное вычисляется операциями построения
  (`L.F`, `L.H` — фронтальная и горизонтальная проекции, `G.*` — плоские построения, `v3.*` — векторы).
  Задача — `{n, q (условие), intro, given (дано), steps:[{t, d, why, add:[элементы чертежа]}], ans, note}`, у задач из
  нескольких пунктов — `parts`. Элементы чертежа: `pt` (точка с подписью A′, A″), `seg`, `line`, `conn` (линия связи),
  `poly`, `curve`, `circ`, `arc`, `dim`, `ang`, `txt`; вид линии `k`: `main`, `res`, `grn`, `aux`, `hid`, `thin` и др.
- `WB3.add` (≈ стр. 4180) перед добавлением задачи меняет десятичную точку на запятую (`WB3.ruDec`) и «доводит» линии (`snap`).
- **Режимы разбора** — `PLAYER.mount` (≈ стр. 4307): «Смотрю» (`watch`) и «Решаю сам» (`try`), шаги, 3D.
- **Тренажёр** (`#/ng/check/gym/…`, ≈ стр. 24200): «Новый вариант» (`GEN` — та же программа на других данных),
  «Найди ошибку» (подсаженная ошибка), «Построй сам».
- **«Проверь себя»** (`#/ng/check`, ≈ стр. 26870): быстрый тест, пробный РК, билеты.
- **Инженерная графика** (`#/ig`): 30 вариантов ДЗ 2 — 3D-модель детали (`IG_VARS`, `IG3`) и генератор листа
  (`IGS.sheet(n,'clean'|'draft')`, `IGUI.igSpec` — какие изображения и где граница вида и разреза).
- **Статистика** — `TRACK(имя, параметры)`: Яндекс Метрика и GA только после согласия на cookie (≈ стр. 8320),
  события учебных режимов — docs/ANALYTICS.md.

## Проверка (`tests/`, запуск `node tests/run.js`, в CI — `.github/workflows/check.yml`)

| Что | Файл | Как |
|---|---|---|
| Чертёж = проекции одного 3D-объекта | `geometry.js` | восстанавливает точки по A′, A″; линии связи, принадлежность, видимость, размеры, утверждения в тексте; число на чертеже = величина в тексте |
| Ответ = условие | `oracle.js` | условие записано геометрически для 125 из 130 пунктов; ответ проверяется линейной алгеброй |
| Происхождение точек | `provenance*.js` | каждая точка помнит, с какого поля построена |
| Точное исполнение | `certified/` | задачи № 46, 47 — протокол в рациональных числах |
| Метод на других данных | `random*.js` | исходные числа искажаются, задача строится заново и проходит проверку |
| Проверка проверки | `mutate.js`, `adequacy.js`, `normo-mutate.js` | подсаженные ошибки в чертежах, в коде задач, в листах ИГ |
| Ложные срабатывания | `false-positives.js` | эталоны и эталоны в другом порядке |
| Нормоконтроль ИГ | `normo.js`, `normo-model.js` | ГОСТ 2.301–2.307, 2.104 по готовому SVG и сверка с 3D-моделью |
| Тренажёры, РК2, теория, обход сайта | `gym.js`, `gen-check.js`, `rk2.js`, `theory.js`, `run.js` | нажатия, шаблоны ошибок, каждая страница на телефоне |

`tests/baseline.json` — разобранные вручную случаи уровня «проверить» (не ошибки) с объяснением.

## Мутации

- `MUTATE_CHECK` (`mutate.js`) — в готовые чертежи: разрыв линии связи, подписи местами, число на 3–9 мм больше.
  `MUTATE_SIZES` — полный перебор всех чисел на чертежах.
- `runAdequacy` (`adequacy.js`) — в код задач: F↔H, не та координата, не тот знак, опечатка в числе, не тот штрих,
  видимая ↔ штриховая. Каждый выживший мутант разобран: данные / условие / оформление / пропуск.
- `ORACLE_MUTATE` (`oracle.js`) — сдвиг точки ответа.
- `wavyMutations` (`normo-mutate.js`) — сторона волнистой линии в листах ИГ.

Запуски по отдельности: `node tests/adequacy.js --per=2 --seed=5`, `node tests/false-positives.js`,
`node tests/normo-run.js`, `node tests/random-run.js --seeds=30`.
