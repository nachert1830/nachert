# Архитектура: один файл — сознательно

Сайт — один файл `index.html` (≈ 30 тыс. строк, 3,2 МБ, по сети — 0,85 МБ в gzip) плюс `sw.js` для работы без сети.
Это решение, а не случайность:

- **Без сборки и зависимостей.** Нет npm, бандлера, фреймворка — нечему устареть или сломаться при обновлении. Файл, который
  открыл студент в 2026 году, откроется и через десять лет.
- **Проверяется ровно то, что видит студент.** Тесты (`tests/run.js`) загружают этот же файл в настоящий браузер (Chromium) и
  проверяют отрисованные чертежи. Между проверенным и опубликованным нет шага сборки, где могла бы появиться ошибка.
- **Работает без сети.** Один файл целиком кэшируется service worker'ом (`sw.js`, версия кэша меняется при каждом выпуске):
  после первого открытия тренажёр работает в метро и в аудитории без Wi‑Fi.
- **Хостинг — GitHub Pages**, публикация — `git push`. Каждое изменение видно в истории коммитов.

## Как файл держится в порядке

Код разделён на модули с собственным пространством имён — каждый объявляет один глобальный объект `window.ИМЯ`
и общается с остальными только через него. Модуль находится поиском по заголовку `/* ═══ ИМЯ` или по `window.ИМЯ =`.

| Модуль | Что делает |
|---|---|
| `WB3`, `L` | 89 задач рабочей тетради: исходные данные, шаги, чертёж каждого шага. Помощники `L.F`/`L.H` — фронтальная и горизонтальная проекции |
| `PLAYER` | Плеер разбора: шаги, подсветка элементов шага, финальный чертёж, 3D |
| `DZR`, `NGLIB`, `SHEET`, `HWCHECK` | Домашние задания НГ и ИГ (у каждого предмета свой раздел ДЗ: `#/ng/dz`, `#/ig/dz`; прежние `#/dz/…` переадресуются): реестр `kernel/dz.js`, по папке на ДЗ в `dz/` (данные вариантов, методика, решатель; оглавление — `dz/README.md`); лист А3 по ГОСТ — `kernel/sheet.js`; «Сверь свой лист» — проверка листа студента числами. `NGHW` — прежний интерфейс примеров |
| `TASK3D`, `DAY3D`, `SPACE` | Задача и тема дня в пространстве, тренажёр пространственного мышления |
| `GEN`, `GYM` | Новые варианты задач тетради, режимы «построй сам» и «найди ошибку» |
| `RK2`, `LEARN`, `TOPICS`, `SYMPTOMS`, `GLOSS` | Подготовка к РК, обучение по темам, поиск «Опиши, что не понимаешь», словарь |
| `LABS` | Лаборатории: 3D-модель и эпюр, натуральная величина, две прямые, плоскость, замена плоскостей |
| `IG3`, `IG_VARS`, `IG_WB`, `IGL`, `IGS`, `IGNK`, `IGREAD` | Инженерная графика: твёрдотельные модели, 30 вариантов ДЗ 2, лист по ГОСТ, обучение на варианте 5 и «Научись защищать точки» (IGL), «Нормоконтроль», «Читаю чертёж» |
| `DMARK`, `LINEFIX`, `FX`, `PANES` | Оформление чертежа (маркеры шага, толщины линий), анимации, раскладка |
| `TRACK` (внутри оболочки), `VIEWS_PROBE` | Обезличенная статистика без cookie (см. docs/ANALYTICS.md) |

Стили — один блок `<style>` в начале, разделённый теми же заголовками; цвета — токены (docs/color-policy.md).

## Что защищает от ошибок при правке

Монолит опасен тем, что правка в одном месте молча ломает другое. Здесь каждое изменение проходит полный набор проверок
(`tests/README.md`), которые GitHub запускает после каждого коммита (`.github/workflows/check.yml`):
3D-восстановление каждого чертежа, оракул ответов, построимость («Евклид»), арифметика текста, ДЗ-оракул на случайных вариантах,
трассировка проекций, нормоконтроль листов, обход всех 363 страниц на экране телефона и прохождение каждой задачи до ответа.
Сами проверки проверены мутационным анализом: в код подсаживаются ошибки и считается, сколько поймано
(цифры — docs/THESIS.md).

## Когда стоит разделить

Если над сайтом начнут работать несколько человек одновременно или файл перестанет укладываться в 1 МБ gzip, следующий шаг —
вынести данные задач (`WB3.add({...})`) в отдельные файлы, подгружаемые по требованию. Код плеера и проверок от этого
не изменится: задачи уже сейчас — данные плюс функция чертежа, без связей друг с другом.
