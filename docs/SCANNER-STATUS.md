## 2. Что не доделано (открытые проблемы, по убыванию важности)

### A. Нет ни одного настоящего замера — главное
1. **Метрика «настоящие листы» не измерена** (пункт Г в 7л: «нет данных»). `lab/private/real/` в git нет и в свежем контейнере пуст. Последний реальный набор — 8 страниц PDF одного студента (вариант 7, листы А4 в клетку): по отчёту 6 из 7 чертежей найдено, **часть опознана у 1**, «верно» 7 после разметки владельца, ложных 0 — но это вердикты в основном по условию.
2. **Режим «Оцифровка Claude» (последняя работа #74–#82) проверялся только на синтетике и на ответах Opus из 7м**; на живом сайте с настоящим листом — не гонялся (живая проверка `scanner-live.yml` — только вручную, платная; ProxyAPI-путь после #79 ею не прогонялся).
3. Нет набора «работа + вердикт преподавателя» → нельзя честно сказать «ложных 0» для реальности. Цифры 0 ложных — только на синтетике и 7 размеченных фото.

### B. Покрытие заданий
4. Поддержано **только ДЗ №3** (4 части) и частично ДЗ №2 (2а по шагам, пирамида/призма/куб). **Нет:** ДЗ №1, №4а (кривые по точкам 1…20), №5 (конус, окружности, касательные).
5. **Только прямые.** Окружности, дуги радиусов вращения, лекальные кривые — не читаются.
6. **Несколько эпюров на листе и масштаб 2:1** (часть 4 бывает 2:1): с глазами/«своими глазами» в принципе есть, на настоящих листах 2:1 не проверен. Изгиб А3 без сетки («чертёж — сам себе линейка») — не сделан.
7. **Ответы и таблица данных на листе не читаются** (нет OCR, подписи почерком не читаются ни шаблонами, ни Qwen). Ответ (H, φ, ψ) студент вводит руками или модель записывает в `T`-строке — не проверено на почерке.
8. Куб (2в): ребро AD невидимо → «не могу утверждать» даже на верном листе; решение за владельцем (не проверять AD или требовать AK тонкой).

### C. Качество входа
9. Настоящие фото — **2,7–3,8 px/мм**, нужно ≥ 6 (а лучше 8+). Съёмка вблизи по чертежам (`cam.html`) есть, но на настоящих листах не проверена.
10. Карандаш на настоящих фото тоньше и бледнее синтетики, блики, изгиб бумаги, чужие пометки/ластик — синтетика всего этого не имитирует.
11. **Хрупкость обычного пути:** страница PDF, перерисованная `pdftoppm`, дала на условии (p-003) два ложных вердикта («г) верно», «б) ошибка»). Ложное «верно» части на чертеже условия — открыто (в 7и/7ж частично закрыто мерой опознания, но на этом фото заново не проверялось).
12. «Ошибка» части без подсказки модели не утверждается вообще (в9 нашла «ошибку» на чертеже части 4) → ошибки в частях 1 и 4 своими глазами ловятся 3 из 5.

### D. Модели и «глаза»
13. Qwen3.6 (Yandex, по умолчанию) **точки угадывает** (промах 14–30 мм, перепутано до трети подписей) и называет часть даже у чертежа только с условием. Полезен лишь как «где чертёж».
14. Claude Sonnet/Opus оцифровывают хорошо (точки ≈ 0,4 мм, линии 91–100 %), **но промахи в связях** (пропущенная линия связи, `B₄–B″` вместо `B₄–B′`). Из-за правила «для ошибки нужно ≥ 90 % линий части» верный лист с ошибкой студента даёт «не могу утверждать», а не «ошибка» (в9 a_dir: «ось x₁₄ отклонена на 8,9° — проверьте»).
15. Оцифровка идёт **одним чертежом за запрос** (Все = 4 параллельных запроса); весь лист одним снимком (3–4 px/мм) моделью не измерен.
16. Зарубежная модель — фото за рубеж → нужно согласие; для остальных студентов (кроме владельца) политика не решена; `EYES_BEST_FOR=admin` — тестовый режим.
17. Замеры в `lab/dz` идут через OpenRouter, продукт — через ProxyAPI: два разных пути, цифры не переносятся один в один.

### E. Скорость
18. Снимок вблизи: **54–68 с при замедлении CPU ×4** (цель ≤ 20 с), целиком лист на среднем телефоне — до ~3 мин. Нужны WebGL/WASM-SIMD или параллельные потоки. Режим оцифровки моделью — 0,4–0,5 с мозга + 6–20 с модель, но платит рублями.

### F. Свои нейросети — не помогли
19. `lab/dz/net/eyes.onnx` (тепловые карты точек): на синтетике 87 % точек, 0,4 с/лист, но **на настоящих фото почти слепа** (11–25 пиков). В сканер не включена.
20. Очиститель карандаша (`lab/dz/cleaner/`): на настоящих фото вердикты не изменились, время ×3 → веса в репозиторий не положены, второй проход отключён.

### G. Организация / долг
21. `lab/dz/REPORT.md` — 125 КБ, нумерация склеена из параллельных веток (7е…7и дублировались при слиянии); `lab/REPORT-scanner.md` описывает **старый** сканер № 46/47 в ветке `affectionate-mayer`. Два параллельных конвейера (старый 46/47 и новый ДЗ №3) с общими `lines.js`, `rectify.js`, но разным интерфейсом.
22. `lab/dz/README.md` говорит «папка не в git», но в git лежит всё, кроме `lab/private/` — устаревшая фраза.
23. `lk/lib/scanner.js` — заглушка-регистратор (`ClubScanner.register`), реальная интеграция идёт через `lk/app.js` → `lab/*.html`.
24. Сервер: `npm test` 81/82 (падает «расписание группы» от даты — и на чистом `main`).
25. Нет режима преподавателя, кнопки «не согласен», истории работ, согласия на хранение фото, статистики ошибок группы (слой L8 в `SYSTEM.md`).
26. Файлы очень «плотные» (строки по 300+ символов, `lab/dz/check3.js` 52 КБ, `eyes.js` 65 КБ, `lk/app.js` 125 КБ) — читать их целиком дорого.

## 3. Почему сканер «ничего не умеет» (честно)

Это не одна поломка, а сумма причин. По убыванию вклада:

1. **Он ни разу не работал на настоящих данных в достаточном объёме.** Вся «надёжность» (0 ложных) доказана на синтетике, которую писали те же люди/модель, что и сканер. Реальных листов — одна пачка из 8 страниц одного студента. Синтетика оптимистична (отчёт сам это пишет): нет бликов, изгиба, грязи, JPEG, настоящего почерка.
2. **Жёсткое правило «лучше отказ, чем ложный вердикт» + строгие пороги, подобранные на синтетике.** Результат: «верно» выдаётся только если построение сошлось почти идеально, «ошибка» — только при доказательстве двумя независимыми линиями и ≥ 90 % найденных линий. Всё остальное — «не могу утверждать». Для студента это выглядит как «ничего не умеет», хотя технически — ноль неправды. Доля вердиктов на старом сканере была 42 %, ошибки частей 1/4 находятся 3 из 5.
3. **Нет «чтения» бумаги как человек читает.** Нет OCR: ни почерка, ни таблицы данных, ни ответов, ни номера варианта из штампа. Приходится угадывать вариант по геометрии (30 гипотез) или брать из профиля. Qwen в Yandex точки угадывает с промахом 14–30 мм.
4. **Низкое разрешение настоящих фото** (2,7–3,8 px/мм при необходимых 6–8): тонкий карандаш и линии связи теряются, допуск мозга становится больше, чем различие между «верно» и «ошибка» (≈ 2 мм / 2°).
5. **Узкий охват.** Умеет прямые линии одной пирамиды ДЗ №3. Окружности, кривые, ДЗ №1/№4а/№5, 2:1, несколько эпюров на листе с изгибом — нет или не проверено.
6. **Свои нейросети не заработали на реальных листах**, поэтому «зрение» держится на дорогой внешней модели (Claude через ProxyAPI), которая ошибается в связях между точками, стоит рублей и недоступна без согласия.
7. **Медленно.** Минута-три на чертёж на телефоне — для пользователя это «сломано».
8. **Нет петли обратной связи.** Нет разметки преподавателя, «не согласен», набора реальных работ с вердиктами. Любое улучшение нельзя проверить, поэтому по правилу проекта (нужно «0 ложных») ничего нельзя ужесточить/ослабить.

## 4. Что делать дальше (предложенный порядок)

1. **Собрать реальный набор** (20–40 листов ДЗ №3 с вердиктом преподавателя) в `lab/private/real/` + `index.json`; прогнать `node lab/dz/real-eval.js`. Без этого всё остальное — на ощупь. *Нужно от владельца.*
2. **Живой прогон «Оцифровки Claude» на 3–5 настоящих фото** через кабинет (владелец с отметкой согласия): записать, где модель ошибается (связи, штриховые, подписи индексов), и подправить `DIGIT_PROMPT`/`prepareDigit`.
3. **Сделать оцифровку устойчивой к пропуску линии связи:** мозг не должен терять «ошибку» из-за одной недостающей линии (добор линии по карте гребней в окрестности ответа модели уже есть — проверить пороги «≥ 90 %»).
4. **Скорость:** вынести тяжёлые проходы `lines.js` на WebGL/WASM или параллельные потоки; на этом фоне оцифровка моделью (секунды) может заменить проход по линиям.
5. **Масштаб 2:1 и несколько эпюров** — проверить на настоящих листах части 4.
6. **ДЗ №1** (только прямые) → затем окружности/кривые для №4а/№5.
7. **Ответы на листе** — не OCR, а проверка гипотезы «записано число, которое начерчено» (или чтение моделью + сверка мозгом).
8. **Кабинет:** «не согласен» → набор тестов, история, политика согласия на зарубежную модель для всех.
9. **Уборка:** переименовать/перенумеровать разделы REPORT.md, склеить два сканера, поправить README про git.

## 5. Как читать код дёшево (чтобы не жечь лимит)

- **Сначала этот файл**, потом по задаче — только нужный раздел отчёта: `grep -n '^##' lab/dz/REPORT.md`, `sed -n 'A,Bp'`.
- Строки кода очень длинные: для поиска использовать `grep -n -o -E '.{0,80}ИМЯ.{0,120}'`, а не читать файл целиком.
- Какой файл за что отвечает — таблица в `lab/dz/README.md`; слои L0–L8 — `lab/dz/SYSTEM.md` §3.
- Серверная часть ИИ — `server/lib/eyes.js` (164 строки, но 23 КБ); развёртывание и переменные — `lk/DEPLOY.md` раздел «ИИ-зрение сканера».
- Не читать: `lab/dz/REPORT.md` целиком (125 КБ), `index.html` (3 МБ), `lk/app.js` (125 КБ), `dz/*/img`, `ig*/ng*`.
- Быстрые проверки без денег и без фото: `node lab/dz/test-grid.js --plain --ns=1,2,5,8,11,14`, `node lab/dz/test-grid.js --eyes --ns=3,8,13`, `node lab/dz/eyes-eval.js --strategy=own --dz2=0 --sheets=10`, `node lab/dz/test-path.js --n=21 --eyes=mock`.
- Живая платная проверка — только вручную: Actions «Сканер — живая проверка на сайте».
