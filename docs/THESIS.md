**Почему 85 % по мутациям кода недостижимо честно.** Из 140 невыловленных мутантов 22 — «пропуски» (построение
изменилось, проверка молчит); остальные 118 — «условие» (80: изменилось само «дано», ловится только сверкой с тетрадью или
вторым вводом условия, как в сертификатах — O9), «данные» (20: другой, тоже верный вариант той же программы) и «оформление»
(18: эквивалентные — другие только длины линий). Даже если закрыть все 22 пропуска, доля будет 412/530 = 78 %. Чтобы считать
честно, доля должна идти по мутантам, которые меняют построение: сейчас 390 из 412 (95 %).

**Найдено новыми проверками.** Ошибка в самой проверке: core/certify.js определял поле проекции по последнему символу
подписи, и «F″ₕ», «H″f» сверялись не с той проекцией ([`a51a9c9`](https://github.com/nachert1830/nachert/commit/a51a9c9)). Ошибок в решениях и чертежах сайта не найдено.
В № 74 а) точка C″ (параллель касания вписанной сферы) на чертеже не выводится из нарисованного — вопрос к владельцу,
поэтому № 74 остаётся в EUCLID_TODO. Блок «Защита точек» берёт 300 случайных точек (Math.random): один прогон из пяти дал
расхождение видимости у очерка фланца Ø110 — это ловит ночная проверка нестабильности.
