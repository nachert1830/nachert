# Штаб владельца: мысли → задачи → сайт

Адрес: **nachert1830.ru/lk/hq/**. Главный экран — **«Разговор»**: говоришь или пишешь в одну ленту, Секретарь (Haiku) понимает, что это — новые мысли, ответ продакту, «запускай», «что там?», «откати», — и передаёт дальше; ответы Штаба приходят в ту же ленту с кнопками. Откат выкатки — задание «rollback» в hq-work.yml (revert слитого PR, быстрые тесты, main).

Открывается кнопкой «Штаб ↗» в пульте `me/`. Вход — тот же, что в кабинете; Штаб открывается только владельцу (роль admin).

## Конвейер

| Шаг | Сотрудник (по умолчанию) | Что делает |
|---|---|---|
| Диктовка | браузер (бесплатно) / Стенограф — `openai/gpt-4o-transcribe` | голос → текст; длинный монолог — «Запись файлом», куски по 4 минуты |
| Разбор | Аналитик — Gemini Flash | стратегия, цели, задачи, идеи, балабольство → карта со связями |
| ТЗ | Продакт — Claude Sonnet 5.5 | диалог по задаче, ТЗ с критериями готовности, разбиение на подзадачи |
| Назначение | Диспетчер — Claude Haiku 5.5 | вид (код / текст / картинка / исследование) × сложность → исполнитель из штата |
| Исполнение | штат (таблица в «Сотрудниках») | текст и исследование — сразу в Штабе; картинка — файл в `img/hq/`; код — Цех |
| Проверка | Ревизор — Claude Sonnet 5.5 | сверяет результат с ТЗ |

Любого сотрудника можно сменить: на каждом шаге (вкладка «Сотрудники»), в каждой задаче (список «Исполнитель») и своей моделью
из каталога ProxyAPI («+ Своя модель»). Каталог и цены — `server/lib/hq/roster.js`; модели с пометкой «проверить» — имена из каталога
ProxyAPI, которые ещё не вызывались: если ProxyAPI ответит «нет такой модели», имя меняется там же.

## Эпики — большие цели (`server/lib/hq/epic.js`)

Эпик — цель, для которой нужно много задач (новая функция, раздел, система). Его ведёт **Главный инженер** (роль `chief`, по
умолчанию Opus; меняется в «Сотрудниках»). Opus работает только здесь: план эпика, разбор провала, задачи с пометкой «ядро».

1. **Появление.** Скажи в «Разговор» большую цель — Секретарь распознает её (intent `epic`); при сомнении он отдаёт текст Аналитику, а
   под разбором будет кнопка «🧭 Сделать эпиком». Та же кнопка — в карточке любой цели или задачи карты.
2. **План — в Цехе** (задание `plan` в `hq-work.yml`, метка `эпик`). В Issue — только цель и контекст, без монолога. Разведчик (Haiku)
   собирает до 1200 строк кода по цели; Главный инженер пишет план JSON: задачи с «что / где / готово, когда / не делать / проверка»,
   сложность, «ядро», зависимости. План проверяет `validatePlan`: 3–30 задач, без циклов и битых зависимостей, у каждой есть где,
   критерии и проверка, сложных и «ядро» — не больше 30 %. Ошибки — один повтор Главному инженеру; второй провал — эпик на паузе,
   вопрос тебе. Бюджет эпика = оценка задач по штату × 1,5.
3. **Утверждение.** В ленте — карточка плана: цель, архитектура, задачи с исполнителями и порядком, вопросы, оценка. Кнопки
   «✅ Утвердить», «✏️ Переплан» (с замечанием — Главный инженер перепишет план), «Отменить». Во вкладке «Задачи» эпик — отдельной
   дорожкой с прогрессом «сделано / всего» и тратами.
4. **Выполнение — по одной задаче** (каждая опирается на влитую предыдущую). Планировщик `epicTick()` берёт первую по плану задачу, у
   которой готовы все предшественники, дописывает в её ТЗ блок «Эпик: цель, архитектура, что уже сделано» (по отчётам исполнителей) и
   отправляет в Цех обычным путём. Исполнитель — по штату; «ядро» — Главный инженер. Планировщик идёт при обновлении статусов и
   **по таймеру сервера раз в 15 минут** (`remind()` → `hq.tick()`), даже когда ЛК закрыт.
5. **Провал или откат задачи** — разбор Главным инженером: уточнить ТЗ и повторить (можно сильнее), разбить на 2–3 задачи
   (зависимости сохраняются), сначала сделать другую задачу или спросить тебя. Не больше 2 разборов на задачу и 5 на эпик —
   дальше пауза и вопрос («▶ Продолжить» с ответом или «Остановить»).
6. **Бюджет кончился** — пауза, кнопки «Добавить 50 %» и «Остановить». Бюджет — на задачи и разборы; план оплачивается до утверждения и в него не входит. Сбой шага планировщика — строкой «⚠️» в ленте (не чаще раза в час).
7. **Приёмка.** Все задачи влиты → Штаб ждёт зелёную полную проверку `main` не старше последнего слияния (если её нет — запускает) →
   Главный инженер коротко сверяет цель с отчётами задач → итог в ленте: что сделано, кто делал, сколько стоило, ссылки на PR.
   Проверка красная — в эпик добавляется задача «Починить main».

Статусы эпика: `draft → planning → review → running → done`; `review → draft` (переплан); `running → paused → running | failed`.
Решения, которых задание не уточняло: «Отменить» убирает эпик в архив из любого статуса; план, не прошедший проверку, ставит
эпик на паузу прямо из `planning`; с паузы можно уйти в переплан (`paused → draft`); задача эпика «на проверке» (без
автовыкатки) держит эпик, пока ты её не примешь. Узлы — в `hqnodes` (тип `epic`; задачи — `task` с полями `epic`, `ekey`, `deps`).

## Предпросмотр: посмотреть до того, как вольётся

Выключи «Автовыкатку» в «Сотрудниках» — и каждая задача кода перед выкаткой приходит в «Разговор» карточкой «👀 Посмотри, как
будет»: ссылка на живой предпросмотр и скриншоты «было → стало» на телефоне и компьютере. Кнопки «✅ Влить» и «✖ Отклонить».
Пока не нажмёшь «Влить», на сайте ничего не меняется. Задачи эпиков ждут твоего решения так же.

- Цех (`hq-work.yml`, задание `work`): тесты зелёные, PR открыт, автовыкатки нет → страница из ТЗ (`#/адрес`, `me/`, `lk/…`; иначе
  главная) снимается `tools/hq-preview.js` на `main` и с правкой; правка вместе со скриншотами (`_preview/`) кладётся в ветку
  **`preview`** (в `main` не попадает). Ссылка: `https://raw.githack.com/nachert1830/nachert/preview/…` (бесплатный сервис отдаёт файлы
  ветки как сайт). Свой адрес вроде `preview.nachert1830.ru` — переменная репозитория `HQ_PREVIEW_URL` (см. ниже).
- «✅ Влить» → метка `влить` → задание `merge`: все проверки PR зелёные — слияние в `main` и полная проверка; иначе — «не вливаю» в ленте.
  «✖ Отклонить» → метка `отклонить` → PR закрыт, задача возвращается к обсуждению.
- Ветка `preview` одна: в ней последняя задача, ждущая решения. Скриншоты привязаны к своему коммиту и не пропадают.
- Кабинет (вход, сохранения) на предпросмотре не работает — сервер кабинета принимает запросы только с nachert1830.ru. Вид страниц — как на сайте.

**Свой адрес предпросмотра (по желанию).** GitHub отдаёт сайтом только одну ветку на репозиторий (у этого — `main` на nachert1830.ru),
поэтому для `preview.nachert1830.ru` нужен отдельный репозиторий с GitHub Pages, куда Цех будет класть предпросмотр, и запись у
регистратора домена: `preview` · CNAME · `nachert1830.github.io`. После этого — переменная `HQ_PREVIEW_URL` в настройках репозитория.

## Сеанс с исполнителем (вкладка «🧑‍💻 Сеанс»)

Живой диалог, как в Claude Code: говоришь — исполнитель ищет в коде, показывает строки, правит, гоняет проверки, открывает PR и
вливает по твоему «влей». Начать — первая фраза во вкладке «Сеанс» (там же выбор исполнителя; по умолчанию — Главный инженер) или
в «Разговоре»: «давай поработаем вместе…» (Секретарь, intent `session`).

- Штаб создаёт Issue «Сеанс: первая фраза» с меткой `сеанс`; твои реплики — комментарии «💬 Владелец: …». Задание `session` в
  `hq-work.yml` (до 5,5 ч, своя очередь у каждого Issue) запускает `tools/hq-agent.js --session`: он опрашивает Issue раз в 8 с,
  на каждую реплику делает ход командами GREP, READ, SCOUT, EDIT, RUN, CHECK, CI, SHOT и заканчивает его `SAY` (ответ) или `ASK`
  (вопрос). `PR: заголовок` — коммит в ветку `hq/session-N` и PR токеном владельца; `MERGE` — только если ты в этом сеансе написал
  «влей» (кнопка «Влей») и проверка PR зелёная, иначе отказ. 20 минут тишины или «Стоп» — итог и выход.
- Ответы — комментарии с ценой хода; вкладка подтягивает их раз в 5 с, пока открыта; каждый ход — ещё и в «Разговоре» со стоимостью
  хода и сеанса.
- Экономия: Claude — через кэш (системный промпт с картой проекта читается за ~5 % цены); большой поиск — `SCOUT:` (Haiku-разведчик
  приносит пакет кода); история больше 120 тыс. токенов сжимается — старые ходы заменяет сводка Haiku.
- Потолок сеанса — 300 ₽ (меняется в «Сотрудниках»): исполнитель останавливается и спрашивает; «продолжай» поднимает потолок на 50 %.

## Вопросы, реплики на ходу, «Сайт просит»

- **Вопрос про код** («почему не печатается лист?») — Секретарь отдаёт его исполнителю, который только читает код
  (`hq-agent.js --ask`, задание `answer` в `hq-work.yml`); ответ со ссылками файл:строка приходит в ленту с кнопкой «Сделать задачей».
- **Реплика к задаче в работе** («кнопку сделай синей») — комментарий «💬 Владелец: …» в Issue задачи; исполнитель читает
  такие комментарии перед каждым шагом и учитывает.
- **Сайт просит**: полная проверка main красная (Issue «main-красный» из `check.yml`) — в ленте один раз, с кнопкой «Починить»
  (ТЗ на починку, исполнитель — по штату для сложного кода).

## Память

Правила владельца («запомни: тексты для студентов — на ты» в разговоре или в «Сотрудниках» → «Память Штаба») — в каждом ТЗ.
Уроки (что не вышло, что откатили, что заметил ревизор) и сделанное — в ТЗ похожих задач (по совпадению слов, без вызова моделей)
и в разговоре продакта. Хранится в `club_config/hqmemory`.

## Цех (задачи кода) — `.github/workflows/hq-work.yml`

1. Штаб создаёт Issue с ТЗ (без монолога и переписки) и метками `исп:<модель>`, `цех`, `автовыкатка`.
2. Исполнитель (`tools/hq-agent.js`) правит код в ветке `hq/issue-N`. Файлов целиком модели не отдаёт: карта проекта и оглавление
   `index.html` с номерами строк (~6 тыс. токенов вместо ~1 млн), поиск, чтение кусками по ≤ 200 строк, правки блоками. У Claude включён
   кэш (формат Anthropic Messages): повторное чтение переписки стоит ~5 % цены.
3. Дешёвая модель на первой попытке — **две попытки параллельно** в отдельных копиях, берётся первая зелёная. Быстрые тесты по карте влияния. Красные — задача уходит сильнее: DeepSeek V3.2 → DeepSeek V4 Pro → Sonnet → Opus (не больше 3 попыток).
4. Зелёные — PR, Ревизор сверяет дифф с ТЗ; с автовыкаткой и полным прогоном тестов — слияние в `main`. Без зелёных тестов в `main` не попадает ничего.
5. **Автооткат**: полная проверка main после выкатки красная → `check.yml` сам запускает откат этой выкатки (задание `rollback`), в ленте — «↩️ Откатил».
6. Отчёт и стоимость — комментарием в Issue; Штаб подтягивает статусы («↻ Обновить статусы», сам — раз в минуту).

### Командная строка исполнителя (`tools/hq-run.js`)

Кроме поиска, чтения и правок исполнитель (одиночный и Архитектор бригады) умеет:
- **`RUN: команда`** — запустить команду в своей копии репозитория (bash, в корне, до 10 минут); в ответ — код выхода и последние
  8000 символов вывода. Так он сам гоняет нужную проверку (`node tests/run.js --only=…`, `node --test …`), смотрит `git diff`, пишет
  временные скрипты в `/tmp`. Каждая команда — строка `--- RUN: …` и код выхода в логе Цеха.
- **`CI: номер_запуска`** — конец лога упавших заданий запуска GitHub Actions (только чтение; запрос делает сам исполнитель своим токеном).

Безопасность: в окружении команды нет ни одной переменной, в имени которой есть KEY, TOKEN, SECRET, PASSWORD, GH_ (значения таких
переменных, если вдруг попали в вывод, заменяются на `***`). До запуска команда сверяется со списком запретов: сеть (`curl`, `wget`, `nc`,
`ssh`, `scp`, `gh`), `git push/remote/config`, `sudo`, `rm -rf /` и `~`, `npm publish`, чтение ключей, `/proc/*/environ`, запись в
`.github/workflows` и `tests/baseline.json`, запись в файлы вне репозитория (кроме `/tmp`). Запрещённое не выполняется — исполнитель
получает отказ с причиной. Задания Цеха берут код без сохранённого токена (`persist-credentials: false`), `.git/` закрыт для READ
и RUN — токен GitHub исполнителю не виден; пушит Цех сам, с токеном в заголовке. Правило в промпте: упал тест — сначала RUN этой проверки и разбор вывода, потом правка, не наугад.
Тесты: `node --test tests/hq-agent.test.js` (идут в задании `server` проверки сайта; карта влияния — `tools/hq-*`).

Метки «в работу» (старая страница `/ceo/`) и «ai-task» обрабатывает тот же Цех. Прежние `company-work.yml` (вливал в `main` при красных
тестах) и `ai-task.yml` удалены.

## Деньги

Все модели — через один ключ ProxyAPI (`PROXYAPI_KEY`). Штаб считает стоимость каждого вызова по токенам (цена производителя × курс
ProxyAPI, по умолчанию 110 ₽/$ — это оценка, точная сумма — в кабинете ProxyAPI) и останавливается на потолке месяца (по умолчанию
1000 ₽, меняется в «Сотрудниках»). Дополнительно можно задать бюджет самому ключу в кабинете ProxyAPI.

## Хранение

Монологи, карта и переписка с продактом — закрытая база YDB (таблицы `club_hqdumps`, `club_hqnodes`, настройки — `club_config`/`hq`).
В публичный GitHub уходят только ТЗ задач кода и картинки.

## Запуск (один раз)

1. Секрет GitHub `GH_HQ_TOKEN` — токен с правами Issues и Contents (чтение и запись) на этот репозиторий. Если его нет, берётся `GH_CEO_TOKEN`.
2. Секрет `PROXYAPI_KEY` уже есть (сканер, Цех).
3. Actions → «Личный кабинет — развёртывание в Yandex Cloud» (club.yml): создаст таблицы Штаба и передаст ключи функции.

Тесты: `cd server && node --test test/hq.test.js` (маршруты, бюджет, Цех, распознавание речи, эпики — с поддельными ProxyAPI и GitHub).

Следующий этап (эпики с главным инженером, командная строка исполнителя, сеанс с Opus) — задание `docs/HQ-NEXT-PROMPT.md`.
