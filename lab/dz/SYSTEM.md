# Сканер ДЗ: система целиком

Этот документ — проект всей системы: что уже работает, чего не хватает и в каком порядке это строить.
Методика и цифры — в `REPORT.md`, файлы — в `README.md`.

Главное правило не меняется: **ложный вердикт хуже отказа.** Каждое решение ниже проверяется этим правилом.

## 1. Что показали присланные листы

Двенадцать снимков настоящих работ: ДЗ №1, №2, №3, №4а, разные варианты. Они использованы только как образец
того, какие бывают листы. Изображений в репозитории нет, в тесты они не входят.

**Задания шире, чем покрыто сейчас.**
- ДЗ №1: равносторонний треугольник ABC со стороной BC на прямой MN; углы наклона высоты и плоскости
  треугольника; натуральная величина отрезка (прямоугольный треугольник сбоку).
- ДЗ №2: пирамида SABC заданной высоты с вершиной на прямой EF.
- ДЗ №3: четыре части; **часть 4 бывает в масштабе 2:1** (так и подписано на листе).
- ДЗ №4а: пересечение поверхностей — **кривые по точкам 1…20**, вспомогательные уровни h₀₁…h₀₈, окружности.
- Конус и прямая (ДЗ №5): окружности оснований, касательные, лекальные кривые.

**Листы устроены по-разному.**
- А3 с рамкой и штампом. **Таблица данных варианта** — в левом нижнем углу, номер варианта — в штампе.
- **Несколько эпюров на одном листе:** части 1–3 ДЗ №3 — каждая со своими осями и своей копией условия.
- Отдельный лист на часть, условие задачи печатным текстом сверху.

**Съёмка — как получится.**
- Лист на столе с фоном, в кадре линейка и руки, тени, тёплый свет.
- А3 заметно изогнут: у края листа линии рамки — дуги.
- Низ листа со штампом обрезан.
- Коллаж из скриншотов — около 1,5 px/мм. По такому мерить нельзя: нужно ≥ 6 px/мм.

**Рисунок.**
- Линии построения очень тонкие и бледные, основные — толстые, невидимые — штриховые.
- Подписи с индексами (A₁, h₀₁, 1″…20″), стрелки, дуги радиусов вращения.
- Ответы — формулами: «φ = 90° − β».

## 3. Архитектура: восемь слоёв

Каждый слой отвечает за одно и может сказать «не могу». Отказ слоя — это отказ всей проверки с понятной
причиной («сильный блик», «вариант не узнаётся»), а не тихая ошибка дальше по цепочке.

**L0. Съёмка** (`capture.js`, `cam.html`). Живая камера оценивает каждый кадр за миллисекунды: лист в кадре,
резкость (относительно лучшего кадра сеанса), свет, наклон, блик, устойчивость. Снимок делается сам, когда кадр
хорош и устойчив 0,4 с. Следующий — только после сдвига телефона: другой ракурс — другой блик и другой шум.

**L1. Геометрия листа** (`grid.js`, `locate.js`). Лист в клетку: сотни узлов сетки, карта по клеткам, связные
области узлов с проверкой номера. А3: рамка и штамп. Результат — карта «мм листа ↔ пиксели снимка».

**L2. Оцифровка** (`lines.js`, `digitize.js`). Середины карандашных линий, отрезки, тип линии, погрешность.

**L3. Понимание.** Какое задание, какой вариант, где O, какой масштаб, сколько эпюров на листе. Всё — проверкой
гипотез по геометрии: условие каждого варианта прикладывается к линиям листа (`calib.js`).

**L4. Измерение «как начерчено»** (`given.js`). Каждая проекция каждой точки условия — отдельно, со своей σ.
Отсюда два эталона: для данных варианта и для пирамиды студента.

**L5. Проверка построения** (`check*.js`, `explain*.js`). Построение — функция свободных выборов студента
(`model3.js`). Ядро находит выборы по листу и проверяет каждый шаг от предыдущего шага самого студента.

**L6. Решение** (`series.js`). Кадры голосуют. Замер — медиана, погрешность — большее из модели и разброса
кадров. Утверждение — только если его делают ≥ ⌈2k/3⌉ кадров и ни один не утверждает обратного.

**L7. Объяснение** (`report*.js`, overlay в `worker.js`). Разбор — на самом фото, в его перспективе: зелёное —
как надо для пирамиды студента, красное — что взято у него.

**L8. Платформа** (личный кабинет, следующий этап). История работ, «не согласен» → преподаватель, набор реальных
работ с вердиктами, правило «версия выходит, только если на этом наборе ноль ложных», отпечатки для
преподавателя, статистика ошибок группы.

## 4. Решения, которых нет у других

| решение | суть | статус |
|---|---|---|
| Условие — это линейка | Координаты условия известны точно: по ним калибруется весь лист, как геодезическая съёмка по опорным точкам | работает |
| Сетка — тысяча опорных точек | Лист в клетку выпрямляется по клеткам до 0,02–0,04 мм, изгиб бумаги не мешает | работает |
| Сетка — как RANSAC | Рост сетки через засвеченную полосу может «сползти» на клетку. Модель сетки (гомография + изгиб) выбирается по согласию большинства узлов; узлы, сходящиеся при сдвиге ровно на клетку, перенумеровываются | работает (найдено синтетикой с бликом) |
| Два эталона | Ответ сверяется и с вариантом, и с пирамидой, как она начерчена: «способ верный, ошибка в данных» | работает |
| Первая ошибка, а не «неверно» | Каждый шаг — от предыдущего шага студента: видно, где именно и почему дальше всё «честно неверно» | работает (ДЗ №2а, №3 г) |
| Серия кадров голосует | Ошибка кадра (блик, тень, смаз) не повторяется в другом кадре, а то, что на листе, — повторяется | работает (`test-series.js`) |
| Погрешность измеряется | σ — не только из модели, а из разброса одного замера по кадрам | работает |
| Последовательная проверка | Кадров ровно столько, сколько нужно: 2, если всё согласно, до 5, если спорно | работает |
| Разбор поверх фото | Зелёное и красное лежат прямо на линиях студента в перспективе снимка | работает (`cam.html`) |
| Вариант — по чертежу | Студент ничего не вводит: условие 30 вариантов прикладывается к линиям, лучший — с запасом | работает (лист в клетку): ложных 0, но на половине листов — «укажите номер» |
| Отпечаток построения | Свободные выборы (уровни, оси, концы линий) — почерк. Совпадение свободного — повод преподавателю посмотреть | работает (синтетика), только «похоже — проверьте» |
| Чертёж — сам себе линейка | Линии по линейке прямые, линии связи ⟂ оси x: изгиб А3 без сетки находится по самому чертежу | следующий шаг |
| Все копии условия | Поиск всех мест, где лежит условие, — несколько эпюров на одном листе, каждый со своим O | следующий шаг |
| Масштаб как гипотеза | 1:1 или 2:1 — что лучше объясняет линии | следующий шаг |
| Таблица на листе — не OCR | Цифры таблицы сверяются с 30 известными таблицами: выбрать из 30 проще и надёжнее, чем распознать | следующий шаг |
| Ответ на листе — не OCR | «Записано ли 22°?» — проверка гипотезы по форме цифр, а не чтение почерка | следующий шаг |
| Ошибка — тоже программа | Типичная ошибка — это другая программа построения: из каталога ошибок генерируются тысячи листов для тестов | работает для ДЗ №2а, №3 |
| Преподаватель в цикле | Каждое «не согласен» становится тестом: система не может повторить ту же ошибку | платформа |
| Статистика потока | «60 % группы взяли 3′ на h′» — преподаватель видит, что объяснить на лекции | платформа |

## 5. Порядок работ

1. **Реальные работы с вердиктами преподавателя** и тест «сканер против преподавателя». Без этого остальное — на
   синтетике.
2. **Кабинет:** `cam.html` внутри кабинета, история, «не согласен», согласие на использование фото.
3. **Несколько эпюров на листе и масштаб 2:1** — без этого не читается половина настоящих листов ДЗ №3.
4. **«Чертёж — сам себе линейка»** для А3 без сетки.
5. **ДЗ №1** (только прямые — ближе всего к готовому), затем окружности и кривые для №4а и №5.
6. **Таблица варианта и ответы на листе** — проверкой гипотез.
7. **Режим преподавателя:** пачка работ, отпечатки, статистика ошибок.
